# v0.12.0 S2 模块验证完成

基线为已由用户确认的 `v0.12.0-s1-board.1`。S1 分支和 local/board 标签已推送。S2 完成独立模块及组合链路验证，生产 top 尚未接入 BGM.PCM，不生成 bit 或 local/board 标签。

## 最终实现

- 扫描器增加 `SCAN_AUDIO`（默认 0）及 audio_found/audio_cluster/audio_size；独立测试开启 1 后查找根目录 BGM.PCM，四图齐全但音频未发现时继续遍历。生产默认保持原行为。
- FAT32 streamer 增加可关闭的 data_permit 数据扇区许可。音频实例等待环形缓冲至少空出 256 样本，FAT 查询仍按共享扇区服务仲裁；图片实例许可恒 1。
- fat32_pcm_stream：保留独立文件游标、碎片簇链、按文件长度截尾、EOF 回首簇循环；≤512 字节短文件首次读取后在 512 字节缓存中循环，避免每个样本重新读取一个扇区。空/奇数字节长度拒绝，错误停止直到重新启用。
- pcm_stream_player：4096×16bit、13bit 指针；源域格雷码经两级同步后转二进制计算水位；2048 预填充、1024 低水位、3072 补充目标；同步 BRAM 读取及 8 项输出队列；相位累加器 48kHz，音量 128/256，左右相同。
- 停止时等待输出队列完成握手，读侧清指针并确认后写侧才清零；循环 EOF 不清环形缓冲。欠载输出零且计数；输出队列长时间背压置 overrun，不覆盖已经呈现的样本。
- 音源 mux 锁定被背压的样本直到接受；未选中的琶音正常消费丢弃。S3 可复用此逻辑或现有 HDMI 桥同类锁定选择，不能将两者接成独立竞争的播放时钟。
- Python 工具实际调用 FFmpeg，输出固定 PCM 格式和统计；默认不覆盖已有输出，`--force` 明确覆盖。生成了 3 秒 440Hz 试听样本。

## 验证结果

| 证据 | 实际覆盖 |

| pcm_s2_player_exact2 | 5,300 个有符号样本逐项比对、多个指针回绕、预填充、欠载、平均采样率、背压保持、停止清空与立即停止后重启 |
| pcm_s2_units_final1 / tb_audio_scan | 六组目录：四图之后跨根目录簇、仅音频、重扫清结果、目录/卷标排除、扩展名、重复条目 |

| pcm_s2_units_final1 / tb_audio_stream | 1202 字节碎片文件循环、并发图片读卡、真实 service/adapter、末扇区截尾、两字节文件循环、在途停止重启、读失败及空/奇数/缺文件 |

## 独立综合

TD `pcm_s2_syn2` 全部通过，源文件与综合快照逐字节一致：

| 模块 | LUT | 寄存器 | BRAM9K |
|---|---:|---:|---:|
| pcm_stream_player | 376 | 177 | 7 |
| fat32_pcm_stream（含文件读取器） | 986 | 269 | 1 |
| audio_source_mux | 39 | 2 | 0 |
| SCAN_AUDIO=1 扫描器 | 1387 | 842 | 0 |

报告确认 4096×16bit 双口 RAM 和 8×16bit 小队列推断。保留 TD BRAM byte-enable 未驱动/初始化值忽略提示；内存内容由有效指针与预填充保护，不依赖上电初值。以上是独立综合，不是布局布线或跨域时序通过；顶层接口展平的引脚数量不是生产板引脚需求。S3 必须检查实际集成资源、Setup/Hold 和 CDC 路径。

## 修正与限制

- 前一轮 `pcm_s2_player7` 仅验证左右声道相同，删掉了样本正确性断言，不能证明播放正确；旧“完成”描述已撤销，最终使用逐样本证据。
- 前一轮草稿的格雷码直接相减、8192 深度、整数采样分频、单拍 valid、单侧重启和未消费琶音均已修正。
- exact1 揭示三目表达式将负数右移变为逻辑移位，改成保留符号位的 16bit 位切片，exact2 通过。
- units1 的两字节文件出现吞吐欠载，新增单扇区短文件缓存后最终通过。较长文件继续流式读卡，不整首缓存。
- reader_final1 的新增端口误连到 BMP decoder，修正接线后 reader_final2 的 42 项通过；保留失败记录。
- 生产播放、顶层重扫联动、HDMI 接线、完整布局布线和板测属于 S3，尚未执行。不将 S1 上板结论外推到音频。
