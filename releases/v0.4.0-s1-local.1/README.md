# v0.4.0 S1 本地上板候选

2026-10-05。**本地验证完成，等待用户上板确认；未推送GitHub，未进入S2。** 下载固定[demo.bit](demo.bit)，不要使用后续可能被覆盖的TD运行目录产物。

## 变化

BMP解析器明确输出加载成功/头失败；控制器仅在成功和SDRAM写完后申请显示交接，实际交接确认后才更新图片编号和音频通知。头失败最多重试一次；MAN保留旧图结束请求，首图/AUTO依次尝试后续候选，最多遍历一轮。全部失败停止自动请求；已有画面可手动重试，无首图时等待复位。

末位E表示加载头失败，保持至下一次成功显示或复位。F/d已预留映射，本阶段不产生超时/不完整错误。扫描时拒绝的头不产生加载错误提示。正常图片编号、KEY1/KEY2、KEY4、模式和音频保持既有约定。

扫描地址两级加法分拍计算，消除新增结果逻辑相关长路径；不改变扫描步长或格式校验。严格头校验、坏图快跳、像素完整性与超时分别在S2～S5实施。本阶段仍不能从SD卡死中自动恢复。

## 验证

- 8个既有入口全部通过（HDMI使用S9配置），控制及缓冲测试在活动目录适配新接口，历史原件未改。
- 新增真实640×480 BMP扫描与307200像素独立RGB比对；正常图恰好一次成功事件。
- 7组真实解析器/控制器恢复场景通过，详见[恢复日志](simulation/recovery_test.log)。失败保持显示缓冲/编号、不发提交音频通知；全坏4图恰好8次尝试后停止。
- 最终扫描加法分拍后重跑完整BMP、恢复专项、6个控制测试，全部零错误零警告；其余回归沿用同轮分拍前结果。仿真中的SD/存储模型不代替实际板级验证。
- TD 6.2.168116综合、布局布线、bitgen完成。3382 LUT、2655寄存器、4 BRAM、1 DSP、2 PLL。固定bit与最终运行产物逐字节一致。
- SD控制域+0.150ns，新增逻辑无负裕量。全局Setup−6.565ns/TNS−295.033ns、Hold+0.011ns，仍有64个SDRAM接口及1个未修改帧缓存内部负端点；详见[时序对比](timing_comparison.md)。
