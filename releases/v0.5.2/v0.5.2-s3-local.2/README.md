# v0.5.2-s3-local.2 刷新修复候选（待 SRAM 验收）

2026-10-07。正式 v0.5.2 已发布产物保持原样；本目录为新硬件候选，不沿用原 SRAM/Flash 验收结果。

本地数据链路、刷新、回归和 TD 检查完成，可以开始用户 SRAM 验收。板级结果见 BOARD_VALIDATION.md，当前全部待反馈。

变更：单 PLL 和 100/40/40(+12 ns)/25/125 MHz 分配不变。SDRAM 包装关闭加密模块内的自动刷新，改为每 1100 个 40 MHz 周期发一次单拍刷新请求；第 900 周期开始阻止新应用突发，第 1000 周期发请求，第 1100 周期恢复。应用突发长度由 256 改为 64，读写前端遵守 Sdr_busy/Sdr_init_ref_vld。100 个排空周期覆盖 64 字在途突发与控制器流水，随后留有 100 个刷新服务周期。正式工程清单补入 sys_pll_s3.v，移除旧双 PLL 源引用，历史文件仍保留。

TD 构建：6.2.168116，EG4S20BG256，`-HighFanoutOptimization -TimingOptimization ultra -PostPlaceOptimization high`。attempt2 已成功产生 629624 字节 bit。全局 Setup +0.128 ns、Hold +0.012 ns，报告内无负端点；覆盖率 99.89%。SDRAM 硬核边界 ext_mem_clk→ext_mem_clk_sft：Setup +6.612 ns、Hold +12.874 ns，48 个端点无负裕量。外部 I/O 延时仍未指定，不能声明所有板级时序均有证明。原始日志及报告在 timing/。

源码快照 source/，清单 sources.txt，bit 与本次 TD 输出逐字节一致。发布 bit 与旧标签不移动。

验证入口：`diagnostics/single_pll/run_refresh_fix.ps1`，生产 FIFO 源码 + 实际受保护 SDRAM 控制器 + 命令/DQ 功能存储模型；不是厂商电气时序模型。仅编译 sdram.v 时定义 SIMULATION 以暴露引脚，严禁把该宏传入加密控制器，否则其读返回时序会改变。

完整数据链路回归已通过：生产读写 FIFO + 加密控制器 + BL4/CL3 命令/DQ 模型，640×480、100/40/25 MHz；119 个可见完整帧、36556800 个可见像素、12 次提交，AUTO、截断重试与保图通过，0 混帧/冲突。78197 次刷新最小/最大间隔均 1100 周期（27.5 μs），0 超期。原始 full_sdram_data.log 保留 16 个警告：14 个厂商 FIFO/上层未用端口连接提示及 2 个厂商常量连接警告，无 Error/Fatal。

命令/DQ 模型是测试侧独立功能模型，依据实际模式寄存器 0x032 实现顺序 BL4、CL3 和四 bank。它检查数据、刷新与在途读写冲突、刷新间隔；不代表完整器件电气时序验证。原来的行为内存只留作独立对照和缓冲所有权计数，显示 FIFO 的输入已来自加密控制器实际 DQ 返回，未用行为内存旁路。

SD 命令/CRC7/CRC16、CMD55 合法 00/01、初始化失败恢复、KEY2 专项通过；稳定性脚本 8 项控制/模式/缓冲/音频/HDMI/视频对齐/复位回归通过。恢复取消的完整数据链路回归通过：8 次提交、36249600 个可见像素，0 混帧/冲突；77586 次刷新间隔全部 1100 周期。覆盖无卡启动、长按恢复、同卡重扫、写中取消、换卡首图、重复恢复丢弃、提交交接、无卡/无图保图及末扇区失败拒绝。
