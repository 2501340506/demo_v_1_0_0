# v0.5.2-s2-local.5 — CMD55 初始化轮询修复候选

验收更新：CMD55 BUG 及剩余扫描/加载中恢复、换卡首图均获用户确认；本候选固定为 [S2 已验收产物](../v0.5.2-s2-board.1/README.md)，bit 不变。以下为当时交付说明。

local.4 已获首图、正常长按保图/MAN/单次提示音通过反馈；拔卡插回可恢复，但偶发首次长按 `00` 后变 F，需要第二次长按。实际失败快照为 `37FF0F / 00001F / 00002F / 00003F`。

卡可能在 ACMD41 返回 idle 后、下一次 CMD55 前完成初始化，此时 CMD55 合法返回 00。旧代码只接受 01，反复拒绝 00 并重发 CMD55，直到初始化总超时。新增引脚仿真在旧 RTL 上复现完全相同的 `00000000000037ff`；修改后同一场景通过。

本版只允许 CMD55 接受无错误的 00 或 01，其他 R1 错误继续拒绝。仍由 ACMD41 确认 ready，CMD16/CMD59 完成后才开放读取。保持双 PLL、全部频率、超时、CRC7/CRC16、保图恢复和四页诊断，不增加自动恢复或插卡检测。

请下载 [demo.bit](demo.bit) 到 SRAM，重点复查首次长按是否仍出现 `00` 后 F，包括正常播放重扫和拔卡报错后插回恢复。实际测试次数由用户反馈记录；不要求把重复次数当作通过标准。如果再失败，先记录四页再重试。

确认首次恢复正常后，继续扫描/加载中恢复和换卡首图。见 [板测表](BOARD_VALIDATION.md)。本版尚未上板验收，不上传、不固化、不进入 S3。
