# v0.5.2 发布后验证补测

本目录记录 2026-10-07 新执行的补测，不是 S3/S4 当时的验证记录。生产源与 `v0.5.2` 对比一致（文本仅归一化 CRLF/LF）；生产 RTL、PLL、约束均未修改，未重新构建。正式 bit 与 S3 local.1、S3 board.1、S4 board.1 逐字节比较一致，均为 629624 字节。

## 可复现入口

在项目根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File diagnostics/single_pll/run_evidence.ps1
```

使用本机 ModelSim SE-64 10.6e，工具目录 `D:/modelsim/win64`。各测试串行编译和运行；日志默认写入 `diagnostics/output/v052_evidence_replay`。刷新断言未通过时脚本最终报错，同时继续运行其余证据测试。脚本检查日志中的 Fatal/Error，不能仅依赖 ModelSim 的退出码。

## 覆盖与边界

|测试|内容|结果|
|---|---|---|
|tb_full_frame_evidence|640×480，100/40/25 MHz，256 字突发；逐像素检查行列及图号、FIFO 空读/溢出、连续翻图、截断重试、AUTO|通过：119 个可见完整帧，36556800 个可见像素，12 次提交，5 次预期错误，0 缓冲冲突|
|tb_full_rescan_evidence|同频率与尺寸；写取消、换卡首图、重扫交接、无卡/无图保图、末扇区失败拒绝|通过：36249600 个可见像素，8 次提交，0 缓冲冲突、0 混帧|
|tb_refresh_service|实际加密控制器与生产读写前端；模拟 FIFO 占用分为空闲、写、读、竞争阶段|失败：空闲 1250 周期，压力阶段最大观测 120284 周期|
|tb_full_refresh_trace|将完整帧测试的生产应用请求送入实际加密控制器，观察外部刷新命令|失败：5893 次刷新，2204 个间隔超限，最大 3088 周期（77.2 μs）|

完整帧测试使用真实 BMP/显示提交/读写/取消控制逻辑，SD 扇区、异步 FIFO 和数据内存使用行为模型。像素域模拟 640 个有效像素、160 个行消隐、45 行场消隐；请求应答带来少量额外场间等待。字节源每 16 个 100 MHz 周期给出一字节。AUTO 计时参数缩短以加速仿真，不是 30 分钟长稳测试。

主完整帧测试的像素图案独立编码图号、行、列，检查 BMP 倒序行映射及逐像素数据；恢复测试使用单色图，检查帧内一致性与换卡首像素。行为 FIFO 模拟两拍指针可见性，不能替代厂商 FIFO 实现时序验证。数据内存固定三拍返回，不模拟物理 SDRAM 刷新停顿。因此完整帧通过不证明实际硬核刷新竞争下的数据无断流。

刷新测试使用未修改的 `sdr_as_ram.enc.v`、`sdr_init_ref.enc.v`、`sdr_wrrd.enc.v`，ModelSim 直接读取受保护模块。以 SDRAM_CLK 上升沿的 RAS/CAS/WE=001 计数实际 AUTO REFRESH 命令。DQ 未连接存储器模型，只测命令服务。初始化完成时刻为 3277862.5 ns（含复位）；当前宏周期 25 ns、计数终值 1249，空闲命令间隔确为 1250 周期。编译有 3 个厂商未定宽常量连接警告，首次优化另有 2 个同源警告，均保留。

饱和占用测试没有真实数据 FIFO，不能将其最大间隔直接解释为板上显示时的最大间隔。120284 周期即 3.0071 ms，说明该压力流量下没有满足计划规定的每次最大 31.25 μs。它也不是 2048 行完整 64 ms 刷新窗口的测量，不据此宣称板上已经发生数据丢失。真实最坏上界尚未证明。

完整帧轨迹探针在控制器初始化后释放应用复位，首图出现后再观察两个帧周期；共发出 376320 个写请求、3379200 个读请求，最大刷新间隔 3088 周期（77.2 μs），超过计划规定 31.25 μs。此时应用仍从行为内存取数据，实际控制器只接收同一请求流；没有把实际控制器返回数据接入显示，也不声称测得板上花屏。生产前端的正常读写发令路径不受 Sdr_busy/Sdr_init_ref_vld 门控；读写持续活动与刷新延迟相关，但受保护逻辑内部根因和修复方案尚未确定。

原始日志和编译日志见本目录同名 `.log`；测试源与执行脚本快照见 `tests/`。通过测试均为 Errors: 0, Warnings: 0；两个刷新测试以 Fatal 结束，这是预期保留的失败证据。最初直接驱动请求的探索日志留在 diagnostics/output，不作为本归档结论的依据。

## 仍不能补造的历史证据

- S4 只有用户整体通过反馈；没有逐次冷启动/拔插时间记录、Flash 校验原始日志或型号后缀。保留该反馈，不虚构逐次结果。
- 外部板级 I/O 延时未指定，不能靠重跑原约束补出不存在的约束条件。
- 实际 SDRAM 数据模型下的刷新竞争、FIFO 断流与端到端像素正确性仍需继续验证；当前失败不能登记成通过。

若后续修复 RTL/刷新策略，必须另建递增候选并重新完成相关仿真、TD、SRAM 和 S4 验收，不能把修复后的结果归到已发布 bit。旧日志、旧产物和旧标签保留。
