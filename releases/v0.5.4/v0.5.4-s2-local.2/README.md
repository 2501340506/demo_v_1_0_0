# v0.5.4-s2-local.2：真实播放事件修正

本地候选，等待用户上板；未建立 board 标签，未上传本修订。S3 暂缓。

[下载 demo.bit](demo.bit) · [板测表](BOARD_VALIDATION.md) · [构建记录](BUILD.md) · [旧日志更正](../../../docs/history/2026-10-07/v0.5.4/S2_log_correction.md)

修复旧版把面板显示码当作事件、扇区为零和重扫漏接的问题。事件来自真实播放器事务；COMMIT 只在显示确认时输出。观察逻辑不改变播放调度、不反压播放器。启动行为仍先完整扫描再加载首图。

D12，LVCMOS33，115200，8N1，发送端。100MHz 控制域，868 拍/位。启动行 `BOOT v0.5.4-s2-local.2`，数字 CR/LF 行尾。队列深度8，快照发送中保持不变。

事件：INIT_OK / INIT_FAIL / SCAN_START / SCAN_DONE / LOAD / RETRY / SKIP / COMMIT / ERROR / RESCAN / MODE / WAIT / NO_IMAGE / STOP / RECOVERED / DROP。

所有数值为十六进制。T 为采集时刻的毫秒计数；I 从0开始（加载/提交对应任务编号，其他对应当前编号）；S 是实际扇区（加载/错误/提交为候选起始扇区，其他为当前读地址）。DROP 的 S 单独表示丢失快照数。E 正常为0，失败沿用 BMP 错误码（1头格式，2读卡/无进展超时，3长度/像素完整性）；D 仅通信失败或初始化失败时带 SD 64位快照。A 为 AUTO 开关状态。

P：0初始化、1空闲、2扫描、3加载头、4写应答、5像素读取、6写完成、7显示确认、8取消、9复位释放。WAIT 记录进入等待阶段，不表示已经超时。同一采样点可含多个事件，按事件位顺序输出，不能把同一 T 内的行顺序解读为事务先后。

验证：独立串口接收器逐字节检查启动行、8N1、CR/LF、字段、时间戳、连续事件、共享快照、DROP=2及恢复发送；真实播放器检查扫描/加载/重试/跳过/提交次数和图片、扇区、错误码；三组重扫交接通过。七套 BMP、三组像素交接、八项既有回归通过。日志保存在 simulation/。

TD 完整综合/布局/bitgen：Setup +0.168ns，Hold +0.019ns，覆盖99.92%；5911 LUT / 3757寄存器，4 BRAM / 4 DSP / 1 PLL。无新增警告类型；既有 PLL/SDRAM 警告未修复，见 timing/WARNINGS.md。bit 629624字节，和最终构建逐字节一致，75个源码/约束文件与工作区和构建快照一致。文件清单见 files.txt。
