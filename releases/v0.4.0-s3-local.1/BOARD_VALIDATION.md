# S3上板步骤

状态：**等待用户确认**。固定[S3 bit](demo.bit)，本地标签v0.4.0-s3-local.1。

## 先确认正常功能

用原来的正常卡下载S3，检查首图、上一张/下一张、AUTO/MAN、首尾循环及提示音；图像方向/色彩和编号应与S2一致。

## 同一张卡比较S2与S3

1. 解压本目录[board_samples.zip](board_samples.zip)，共6张图。使用没有旧BMP残留的测试卡，仍需满足连续文件且位于扫描范围内的既有要求。
2. 先复制`01_skip_1600x1200_yellow.bmp`与`02_skip_32bit_magenta.bmp`，再复制其余4张good图片。目的是让不支持图片尽可能排在正常图片之前；文件名本身不决定扇区位置。
3. 卡内内容保持不变，先下载已通过的[S2 bit](../v0.4.0-s2-local.1/demo.bit)。重新上电或复位，记录从复位到首张正常图片出现的大致时间。
4. 换下载本目录S3 bit，同样复位并记录时间。建议各做3次，比较通常表现，不必精确到毫秒。
5. 两版都应只显示红、绿、蓝、青4张，白条在上、黑条在左；黄色大图和紫色32位图均不显示。S3在扫描经过这两张不支持图片时应更快，且不能漏掉后面的正常图。

不要用S2那两张“头已经损坏”的黄色/紫色测试图代替本轮样图：S3只对结构/长度可信但显示格式不支持的文件快跳，损坏头继续逐扇区扫描。

若两张不支持图实际排在已找到的4张正常图之后，则扫描会先结束，可能看不到加速；记录实际现象即可，不据此直接判失败。本地仿真已固定排列实测快跳次数，板测用于确认实际卡中正常图片仍能找到。初始化/空白区扫描不会被本阶段加速。

## 请反馈

- 正常翻图、AUTO及提示音：待确认。
- 6图测试卡仅显示4张good图、无缺图：待确认。
- 同卡S2和S3首图等待时间或直观差异：待确认。
- 其他异常：待确认。

S3通过后再建立board标签、推送并进入S4。现有SD复位/拔卡问题未修，S3不包含超时。时序仍未全局收敛，见[报告](timing_comparison.md)。
