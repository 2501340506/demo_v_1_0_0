# v0.7.0：FAT32 文件系统升级

正式 bit：[demo.bit](demo.bit)，629624 字节，逐字节复用 v0.7.0-s3-local.1 经 v0.7.0-s3-board.1 验收的原 bit。S4 只做归档和发布，没有修改生产源码或重新构建。

## 功能与使用

使用 FAT32 卡，根目录放 PIC1.BMP～PIC4.BMP；支持缺图，按编号压紧列表。图片须为现有显示尺寸的未压缩 24 位 BMP。支持直接引导及 MBR 首个 0B/0C 主分区、根目录全部扇区和后续簇链、碎片文件和超过旧 64 MiB 扫描范围的文件。

保留原按键、轮播、音频、数码管、双缓冲和长按 KEY2 重扫。数码管/音频编号对应列表位置；例如仅 PIC1/PIC3 时显示编号为 1、2。目录文件大小限制读取；头部预检拒绝明显截断或不支持格式。SD 错误/超时停机后可重新插卡并长按 KEY2 约 3 秒恢复。

## 验证与证据

- 本地：核心 42 场景、包装器 42 素材加 5 模式、最终 16 个回归入口通过。
- 物理实现：TD attempt7 Setup +0.104 ns / Hold +0.014 ns；8890 LUT、5686 寄存器、4 BRAM、2 DSP。
- 板级：用户确认正常功能、两项顺序播放和特殊 FAT32 布局功能正常；首图主观约 4 秒。历史串口的两次错误是主动拔卡/换卡，随后恢复。
- 实际介质：根目录链 2→230；PIC2 为 9 段碎片，最高已用 LBA 304480；PIC4 为 306544，均超过旧上限 131071。特殊布局板测依据用户反馈，没有新增串口日志。

## 已知限制

不支持 GPT、扩展分区、子目录、长文件名或文件写入；固定四个短文件名，512 字节扇区、1～128 个扇区/簇。簇链遍历上限默认 8192，不进行文件系统修复。

空目录、坏格式/真实截断、精确读取中取消及长期稳定性未单独确认板测，已有仿真结论不能替代这些实测。UART 启动文本仍显示历史版本，烧录请按本固定路径确认。诊断地址为最近实际请求的物理 LBA，LOAD 事件时可能仍显示预检地址。
