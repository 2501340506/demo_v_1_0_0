# S3 local.1 上板步骤与反馈

文件：[demo.bit](demo.bit)，候选 `v0.8.0-s3-local.1`。本阶段首次把四 bank 缓存接入生产；2026-10-09 已获用户功能板测确认，实际范围见 [板测记录](BOARD_RESULT.md)。下表保留原测试清单，未逐项确认的内容仍标为待测。

## 下载准备

1. 使用既有 FAT32 TF 卡，根目录放置 PIC1.BMP～PIC4.BMP，均为 640×480、24 位 BMP；最好颜色明显不同并有上下方向文字。
2. 接好 HDMI、TF 卡和下载器，将 SW2 SW1 设为 00（图片模式）。按通常的 TD 下载流程，把本目录固定 bit 下载到 SRAM。
3. 可选连接既有 D12 UART、115200/8N1。四图补齐会出现四个 CACHE_DONE；之后缓存切换应出现 CACHE_HIT 和 COMMIT，不应再出现 LOAD。UART 的 I=0～3 对应面板 1～4。

## 功能检查

| 操作 | 预期 | 结果 |
|---|---|---|
| 启动 | 首图完整后先显示，其余图片在后台加载；无倒置、串色、条纹或持续花屏 | 待测 |
| 四图补齐后快速往返 | KEY1 上一张；KEY2 短按松手下一张；首尾循环，缓存命中不重新读卡 | 待测 |
| 后台加载期间操作 | 已缓存图片可切换；未缓存目标等当前文件完成后优先加载，不能出现半帧或错误图片 | 待测 |
| 连续按键 | 同向挂起合并；下一张优先于上一张，无丢失显示交接或错误编号 | 待测 |
| KEY4 切换 AUTO / MAN | 约 3 秒 AUTO 保留；后台完成不重置计时、不自行切图；切回 MAN 不撤回已接受请求 | 待测 |
| 图片和声音 | 面板编号与实际显示提交一致，每次提交提示一次；后台缓存完成不响 | 待测 |
| 长按 KEY2 超过 2 秒（可按约 3 秒） | 重新初始化与扫描，旧图持续显示直到新首图完整提交；松手不额外翻图，恢复后回 MAN | 待测 |
| 加载中及缓存全满时分别重扫 | 均能保留旧图并恢复，不覆盖正在显示的 bank | 待测 |
| 缺图 / 无图 / 异常卡（有条件时） | 缺图编号压紧；失败保留旧画面；恢复可用卡后再次长按能恢复 | 待测 |

缓存命中的延迟从消抖后的请求计算，为下一次可用帧边界，不称为零延迟。未命中仍需等待 SD 加载。

S4 再用最后验收的同一 bit 验证 Flash、冷启动及持续播放，本次不要求预先填写这些结果。

## 反馈

请说明使用 `v0.8.0-s3-local.1/demo.bit`，反馈首图、四图往返、后台操作、AUTO、重扫保图、提示音是否正常，以及未测项目。异常请补充按键顺序、当前图片/面板状态、照片或 UART 片段（如有）。

实际结论：**S3 功能板测通过**，标签 `v0.8.0-s3-board.1`。用户确认快速切图、重扫及无图数码管状态；其他专项不补填通过。继续按 [S4 步骤](../S4_VALIDATION.md) 验证同一 bit。
