# v0.25.0 S5 候选 5：修复切换场景后第一张图的图例缺字（Seed 7）

候选 `v0.25.0-s5-local.9`，源码提交 `01f3a18`，构建 `lut25_hud7_td_s7`。取代 [s5-local.6/.7](../s5-local.6/README.md)。与 [s5-local.8](../s5-local.8/README.md) 源码相同、只差布局种子。s5-local.8 有问题时用这个。

**卡不用换**：配 [s5-card.2](../s5-card.2/README.md)（整段旁白字幕）或 s5-card.1 都可以。

## 修复的问题

用户板测发现：每次进入一个新场景，第一张图左下角的图例会缺字，像是被上一个场景的图例覆盖。

**原因**：选新场景时板子会从该场景目录重新加载 FONT/TEXT。文字解析器把每段文字的起点和长度记下来，只在三种情况下重新读 TEXT.BIN：文字有效标志掉下来、阶段号变了、预警切换。加载只有几百字节、几毫秒，而叠加层每帧（16.7 ms）才取一次资源状态，所以通常根本看不到有效标志掉下来；新场景又都从阶段 1 开始，阶段号也没变。于是解析器沿用上一个场景的段起点和长度去读新 TEXT.BIN，图例（还有标题）显示错位或截断；按 KEY2 换阶段触发重新解析后才恢复。

**修复**：SD 侧每完成一次 FONT/TEXT 加载就翻转一位“资源代号”，随资源状态一起送到视频侧（用资源字里原来空着的一位）；叠加层看到代号变化就重新读 TEXT.BIN。宣讲模式的旁白字幕用同一块文字存储器，同样加了。

**证明**：新增的测试（`diagnostics/lut_opt25/run_card_switch.ps1`）按板上情况做：第一个场景显示阶段 1 并已解析，再在有效标志不掉的情况下加载下一个场景的 FONT/TEXT，阶段保持 1，检查之后每一帧的每个像素。**s5-local.6/.7 的叠加层在滑坡→泥石流→山洪→地震→滑坡四次切换里全部失败**（标题 y=32、图例底带 y=412 仍是上一个场景的）；本候选四次全部通过（`validation/card_switch.log`）。
