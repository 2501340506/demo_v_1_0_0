# LUT 资源裁减 S1–S3 + 复位修复本地候选（Seed47）

候选 `v0.24.0-s3-local.2`，源码 `ef0eaaf`，构建 `lut24_s3fix_td01`。与 [s3-local.3](../s3-local.3/README.md) 源码相同、只差布局种子，**两个都需要上板**。功能不变，沿用当前卡。

## 修复内容

`s3-local.1`（Seed47）上板卡在 SD 初始化 CMD59（约 6–8 秒后 ERR:05、数码管 `3b000F`），同源码 Seed43 对照构建开机即 `0E`（扫描到 0 张图）。两次的最终网表中，SD 命令模块和读卡器/扫描器的异步复位都由 LUT 对多位状态译码驱动（`S_RECOVER`、`SC_RESET`）；状态多位同时翻转时译码输出可能产生毛刺，静态时序与仿真都不检查。这两处译码在 v0.23 中已存在。

现在三处复位都改为寄存器直接驱动、译码放在寄存器 D 端：`sd_card_top.v` 的 `protocol_rst`、`sd_card_bmp.v` 的 `parser_rst`、`fat32_bmp_reader.v` 的图头解析器复位（S3 后它也服务解码器）。复位延后一拍，协议顺序不变。最终网表复核：SD 命令模块与 SPI 主机的所有复位引脚都来自寄存器；扫描器复位是两个寄存器的或非，无状态译码（`reports/audit/reset_drivers.txt`）。

根因由板测确认；本地结果不代替上板。

## 使用

1. 烧录本目录 [demo.bit](demo.bit)，沿用当前卡，上电或 KEY3 复位，多试几次。
2. 检查开机首图、四宫格菜单（SW3）、宣传四页字幕/语音与 AUTO、四场景四阶段与预警、参数调节、拔卡时的数码管错误页。
3. 若失败请记录屏幕 ERR 码、数码管四页内容和上电到出错的秒数。

## 本地结果

Setup +0.130ns、Hold +0.030ns，STNS/HTNS=0；16926 LUT（基线 18183）、10081 寄存器、53/2 BRAM、12 DSP。修复后 S3 回归全部重跑通过：BMP 头/解码器/文件流/音频控制/语音等价、字幕单元、FAT32 reader 42 例×2、控制器 case0–23、快速启动指标与 v0.23 逐行一致；引脚级 SD 启动仿真与 v0.23 一致（仅复位寄存多 20 ns）。约束、字库 ROM、告警审计通过，详见 `reports/audit/`、`validation/`。
