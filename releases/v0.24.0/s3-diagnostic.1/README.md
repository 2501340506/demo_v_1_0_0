# S3 布局对照构建（仅定位）

**仅用于 A/B 定位，不是修复。** 源码与 `v0.24.0-s3-local.1` 完全相同（`9c87a41`），只换布局种子（Seed43，构建 `lut24_s3_td04`）。标签 `v0.24.0-s3-diagnostic-local.1`。

## 背景

`s3-local.1`（td03，Seed47）上板每次失败：上电约 6–8 秒后屏幕 `ERR:05`，数码管末位 `F`，第 0 页 `3b00`（最后一条 SD 命令为 CMD59），第 1–3 页 `0000`（从未读扇区）。6–8 秒与 SD 初始化超时 2 秒×（首次+3 次重试）一致，故障在 SD 初始化阶段，未到 FAT32/图片读取。用户确认之前的 v0.23 诊断 bit 同卡同板正常。

已核对：SD 驱动（`sd_card_top/cmd/sec_read_write`、`spi_master`）和约束与 v0.23 逐字节相同；引脚级仿真（真实 SPI 驱动+按协议应答的卡模型）v0.23 与 S3 命令序列、初始化、读扇区和扫描结果完全一致；SCLK/MOSI/nCS 输出时序与 v0.23 相同，MISO 输入采样寄存器位置变化但 Setup/Hold 均为正。静态分析无法解释，需要板上对照。

## 使用

烧录本目录 [demo.bit](demo.bit)（675020 字节，与 td03 的 bit 不同），沿用同一张卡和同一块板，上电或 KEY3 复位，请反馈：

1. 是否正常启动（开机首图）；
2. 若失败：屏幕 ERR 码、数码管四页内容、上电到出错的大致秒数；
3. 同样复位/断电多试几次，结果是否一致。

判读：本构建正常 → 故障与具体布局相关（物理实现），下一步做布局约束或采样路径的定点处理；本构建同样失败 → 更可能是设计改动在真实卡上的行为差异，仿真未覆盖，需要回到逻辑层定位。

## 本地结果

Setup +0.191ns、Hold +0.024ns，STNS/HTNS=0；17107 LUT、10045 寄存器、53/2 BRAM、12 DSP。约束、字库 ROM、告警审计与 td03 相同（见 `reports/audit/`）。验证日志与 s3-local.1 相同源码，见 `validation/`。

回退：[v0.23.0 诊断 bit](../../v0.23.0/s2-diagnostic.1/demo.bit)。`s3-local.1` 板测失败，不建 board 标签，原样保留。
