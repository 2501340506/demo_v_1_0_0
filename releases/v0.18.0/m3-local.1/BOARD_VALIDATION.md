# 宣传模式 M3 板测清单

固定候选 `v0.18.0-m3-local.1` 已形成，本清单尚待用户执行。使用 `releases/v0.18.0/m3-local.1/demo.bit`，不要使用会被重建覆盖的 diagnostics/output bit。记录显示器、供电、卡容量/格式、候选标签及异常照片/操作；换卡后复位，不做免复位热插拔。

## 1. 素材准备

准备 FAT32 卡，在根目录复制 `tools/publicity/geohazard_basics/generated/` 的 EDU1–4.BMP（可连同 VOI1–4.PCM），再复制 `tools/scenes/m6_demo/generated/` 的 PIC1–4.BMP、SND1–4.PCM、FONT.BIN、TEXT.BIN。两套图共八张，名称不要互相改写。另一套场景使用 `tools/scenes/flood_village/generated/` 对应十文件。原卡保留备份，用额外测试卡验证缺文件/坏文件。

M1 VOI 是测试音，无正式配音；本候选宣传模式统一静音，VOI 不播放，宣传 AUTO 禁用。情景仍播放 SND/BGM 或原提示音。本阶段不验收讲解或五秒轮播。

## 2. 启动与手动操作

1. `{SW2,SW1}=00` 上电/复位：完整 EDU 优先进入 EDU 第1页，页码1/4，AUTO关闭；等待淡入完成，确认无灾害着色、场景中文或声音。
2. KEY2 短按并释放，按1→2→3→4→1循环；KEY1 按下按1→4→3→2→1循环。KEY1持续按住只退一张，松开不再翻页。
3. 宣传 KEY4 短按多次，保持同页至少10秒，确认没有三秒轮播。再次手动前后翻页仍可用。
4. KEY4 长按至少1秒只切一次；持续按住、再释放，不触发AUTO，不反复切换。从情景再长按回宣传第1页，两方向都检查。

## 3. 四 bank 重载与拨码独立

1. 在EDU第2/4页和PIC第2/4阶段来回切换至少十次，观察淡出、加载、首图与淡入；不能闪出另一套同号图、旧缩略图、错误标题或半帧。加载时试按其他键，加载结束后释放全部键再操作。
2. 在预览、普通转场及情景预警中返回00再长按切应用；确认可退出并完成切换，警报淡出停止、宣传静音。首图必须为目标第1页/阶段。
3. 两种应用分别走00→01→10→11→00；01调亮度/音量、10调对比度/音量，KEY4选参数、KEY1/2减加、组合恢复。参数值和应用身份保留，参数页长按KEY4不切应用，场景速度条不遮B/C/V。
4. 按住KEY4或KEY2跨拨码页，返回00后先释放再按；确认不沿用旧长按计时或产生意外切图/切模式。
5. 11只显示当前套资源，KEY1/2改焦点、KEY4提交；返回00确认页号正确。跨应用后不能看到旧套缩略图。

## 4. 情景回归

1. 进入情景从阶段1、非预警、AUTO关闭开始；KEY2短按下一阶段，KEY1短按切预警/退出；KEY1长按一秒切1X→2X→4X，释放不误切预警。
2. KEY4短按打开情景AUTO，必须等当前动画达到终态并显示完整终态帧才切阶段；01/10/11不自动推进，回00重新确认终态帧。
3. 调速后切宣传再回情景，速度保存；AUTO与预警清零。确认SND分阶段、警报与普通文案、BRAM字库/缺字库回退正常。
4. 分别使用示意村与山洪村；换卡复位后重复上述操作，不能沿用旧卡FONT/TEXT或缓存。

## 5. 兼容与故障恢复

1. 旧四PIC卡、无EDU：启动COMPAT，原前后翻页及短KEY4三秒AUTO保留；四PIC完整时长KEY4进入情景，再长按回COMPAT。
2. 缺EDU2或EDU4表头损坏：启动COMPAT；缺PIC2的双套卡：启动宣传，长KEY4拒绝切情景并提示NO SET，当前页仍可翻。缺目标不应破坏当前图。
3. 无可用图卡：显示ERROR/黑场，不能卡死或发旧音。准备好有效卡，换卡复位恢复；同卡文件修复后的KEY2长按两秒重扫仅用于受控读卡测试。
4. 若实际出现重载读卡失败/ERROR，记录当时源/目标页与现象：KEY4短按重试当前目标，KEY4长按请求另一套可用资源，KEY2长按两秒物理重扫；失败后允许黑场静音重载，不承诺旧缓存瞬时恢复。不要在写卡时让板卡继续读卡。

## 6. 回传

提供候选标签、bit路径、卡素材来源、执行项目及异常；没有实测的项保留待测。本阶段不要求借用旧版时长/冷启动数据。可记录两个方向切换耗时（KEY4达到一秒阈值至目标首个完整画面），注明起止口径。整机≥40分钟、Flash冷启动、正式讲解与五秒AUTO仍属后续M4–M6验收范围。

板测失败保留local.1；修复后生成递增local候选。用户明确确认具体候选后才记录board，不补前序M6的验收结论。
