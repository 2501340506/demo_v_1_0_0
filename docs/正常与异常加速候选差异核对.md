## 源码究竟改了什么

两份实际构建的 `user_source` 均为 134 个文件，133 个逐字节相同；仅 `hdl_source/SD/sd_card_bmp.v` 不同，33 行新增、2 行替换。

- 接出 `fat32_bmp_reader.fat_error`，供上层保存底层原因。
- 新增 `page_error[0:3]`，逐页保存 FAT/扇区、BMP 或内存写入错误，避免后续背景加载覆盖目标页的原因。
- 新增 `diagnostic_target` 和 `failed_request_detail`，把用户请求失败与对应页的错误关联。
- 上层错误 03 有细分原因时，OSD 显示细分错误；成功加载、提交显示或重新扫描时清除相应记录。

当前源码对应入口：`sd_card_bmp.v:416`（FAT 错误信号）、`:712`（逐页记录）、`:762`（OSD 选择）、`:943`（底层端口连接）。[完整源码差异](evidence/page-candidate-comparison/production.diff)。

`load_start/load_index`、`cache_valid`、调度状态机、PIC4 存储地址、AUTO 与按键控制均未修改。新增记录读取原有控制信号，不向原有读图/缓存/切页控制返回控制信号。顶层的 `osd_error_src` 只送状态 OSD 和宣传状态显示的 CDC；宣传字幕播放条件仍取音频状态位，不由新增错误记录启动或停止。

FAT 错误输出在旧版虽然未接顶层，parser 内部仍会用它形成 `mapping_ready`；不能声称旧版整套 FAT 错误逻辑都被综合删除。连接输出会改变保留逻辑和扇出，具体器件映射还会受全局优化影响。

## 实际物理实现差异

两次原始构建均由 TD 6.2.168116 完成。本次读取已存在的布局布线数据库，执行 final timing 分析，没有重新综合、布局布线或生成替代 bit。

| 指标 | 异常旧版 | 正常新版 |
|---|---:|---:|
| LUT | 18176 | 18183 |
| 寄存器 | 12052 | 12119 |
| BRAM9k / BRAM32k / DSP | 53 / 2 / 13 | 53 / 2 / 13 |
| 全局最差 Setup 裕量 | +0.046 ns | +0.039 ns |
| 全局最差 Hold 裕量 | +0.085 ns | +0.073 ns |
| Setup / Hold TNS | 0 / 0 | 0 / 0 |
| MISO 输入 Setup 裕量 | +4.765 ns | +6.000 ns |
| MISO 输入 Hold 裕量 | +1.827 ns | +0.963 ns |
| MISO Setup 路径数据延迟（含 21 ns 输入延迟） | 27.064 ns | 25.829 ns |
| MOSI / nCS 输出 Setup 裕量 | +17.313 ns | +17.313 ns |
| MOSI / nCS 输出 Hold 裕量 | +8.879 ns | +8.879 ns |
| SCLK 输出 5 ns 预算的剩余裕量 | +0.380 ns | +0.380 ns |

MISO 两版的起点均为 B14 输入，终点均为 `spi_master_m0/MISO_shift_reg[0]_syn_4.d[0]`，输入延迟、多周期约束、时钟及采样 RTL 相同。其采样寄存器的物理位置从 `x029y028z0` 变为 `x026y005z3`；路径仍为 5 级，但 LUT 拼接和布线不同。这是读卡路径确有变化的直接证据。

新版 MISO Setup 增加 1.235 ns，同时 Hold 减少 0.864 ns；全局最差裕量也略小。因此不能笼统说“新版整体时序更好”，也不能凭该路径变化认定读卡时序已经是查明的根因。两版在现有约束和工具模型下都通过；实际卡响应、板级信号和运行故障点尚无对应测量。

两份告警审阅 JSON 逐字节相同，综合 73 条、物理 7 条，无新增归一化告警签名。两版都有 SDRAM 实例位置调整和 1 条局部时钟布线告警；局部时钟均为 `ext_mem_clk_sft -> U3/u2_ram/SDRAM_CLK`，不能把共同存在的告警说成已定位的新原因。这里是芯片集成 SDRAM 接口，不是遗漏了顶层外部 SDRAM DQ 管脚约束。

## 对原故障的解释边界

旧版 `errors:03` 与数码管 `0D` 都来自上层 `sticky_error==3`，表示目标图片请求失败；它们不直接指向 BMP 格式、FAT 链、SD 扇区或内存 bank3。所有场景 PIC4/预警异常也不足以单独证明第四缓存地址有错。

本次确定了“相同业务控制源码、不同诊断电路及不同物理实现、不同板测反馈”。物理实现相关的敏感问题是后续排查方向，但当前没有旧版故障时的底层原因、示波器记录或同条件多次 A/B 测试，尚不能排除运行初态或其他条件。新增诊断版现在运行正常，也就没有捕获到原故障细分码，不能倒推成已经完成根因修复。

现有真实 SDRAM 与 HDMI 联合仿真曾在场景等待处停止，仍属未完成，未改记为通过。本次比较未改 RTL，不重新跑已通过的专项和完整 TD，也不借新增报告补写板测次数或性能数据。

## 保留与复查

当前使用用户确认正常的 [诊断固定 bit](../releases/v0.23.0/s2-diagnostic.1/demo.bit)；[旧版异常 bit](../releases/v0.23.0/s2-local.1/demo.bit) 原样保留作为对照，既有 local/board 标签均不移动。

证据：[比较 JSON](evidence/page-candidate-comparison/comparison.json)、源码差异及两版 MISO/输出路径报告同目录。生成工具为 `diagnostics/disaster_selector/compare_page_candidates.py` 和 `compare_page_timing.ps1`，读取本地保留的两次构建目录；执行后检查 `comparison.json`，配置 `.diff` 为空表示归一化后一致。时序脚本拒绝覆盖已有同名审计日志。

如继续查明根因，应优先围绕旧版实际失败事务抓取 SD/FAT/BMP/写入状态，再做同板同卡同启动条件的重复 A/B；当前不根据上述相关性盲改 bank3、采样沿或约束。该后续工作未在本次只读对比中执行。
