# v0.5.3 `bmp_read` LUT 优化分阶段计划

## 目标

仅优化 `user_source/hdl_source/SD/bmp_read.v`，保持接口、BMP 支持范围、SD 读取协议和图像显示行为不变。当前基线中 `bmp_read` 约 870 LUT，目标是降低该层级 LUT，并保持 ModelSim 与 TD 验证通过。

## 阶段

1. **S0 基线**：保存 v0.5.2 对应 area、timing、源码和构建信息到 `releases/v0.5.3/v0.5.3-baseline/`。
2. **S1 RTL 优化**：逐项评估常量乘法、头部字段存储、扇区长度运算和重复扫描地址；只保留实际降低资源且功能等价的改动。不修改模块接口及其他 RTL。
3. **S2 ModelSim**：运行 BMP 头解析、扫描、加载、短扇区、读失败、超时和既有回归，日志要求 0 errors、0 warnings。
4. **S3 TD 构建**：完成综合、布局布线、时序、面积和 bitstream，比较 `bmp_read` LUT、顶层 LUT 和关键路径，候选保存至 `releases/v0.5.3/v0.5.3-local.1/`。
5. **S4 文档**：更新项目 README、CHANGELOG、验证状态、HANDOFF 和版本说明，建立本地计划/候选标签。
6. **S5 上板后定版**：等待用户上板反馈；通过后再建立 board/正式标签并归档到 `docs/history/<日期>/v0.5.3/`。上板前不上传 GitHub。

## 实施与验收规则

每项试验保存源码、资源和时序记录。以同一工具、工程清单及约束进行比较；分别列出综合与布局布线资源，不能混用两种口径。位宽只在完整输入范围允许时缩减，不将动态宽高硬编码为 640×480。保持扫描跳过非目标 24/32 位 BMP、短扇区、超时及重新启动的行为。七套 BMP 专项、真实解析器异步交接、八个既有回归入口须通过，日志检查错误、警告及 PASS 标记。

本地候选使用 `v0.5.3-local.1`，如板测需修改则递增 local 编号；用户确认具体候选通过后创建 `v0.5.3-board.1` 和 `v0.5.3`，正式产物复用已验证 bit，不重建。更新 README、CHANGELOG、验证状态、文档索引和 HANDOFF，记录当前任务、完成项、卡点、下一步和踩坑。

结项时将完成计划、最终 HANDOFF、验证状态及归档索引复制到 `docs/history/<实际日期>/v0.5.3/`，活动计划保留归档链接。保留历史产物，不批量删除。GitHub 推送等待用户上板验证和明确上传许可。

## 验收边界

基于最新已验收 I/O 修复工作区，保留现有时钟、约束和 SPI 分频。ModelSim 行为模型不能替代板级验证；要求 Setup/Hold 无新增负端点，不放宽约束换面积。板测包括首图、手动翻图、AUTO、重扫恢复、无图提示、视频及提示音；不额外强制规定冷启动次数或长稳时长。记录用户实际结果，不把免测写成实测。
