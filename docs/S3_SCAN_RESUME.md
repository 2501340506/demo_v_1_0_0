# S3 扫描暂停与续扫接口

本阶段基线 `v0.5.4-s2-board.2`。local.1板测首图花屏，而S2解析器加S3原启动字符串的对照bit已获用户确认正常。local.2改用 `ENABLE_SCAN_PAUSE=0` 编译期关闭生产暂停逻辑，同时请求和续扫输入保持0；专项仿真显式设为1。首图调度、后台续扫、扫描期间按键策略属于 S4。local.2现已获用户确认板测功能正常，但不能据此宣称已确定local.1花屏的具体物理根因。

## 接口约定

接口位于 `bmp_read`，与解析器同一个100MHz控制时钟域。

参数 `ENABLE_SCAN_PAUSE` 默认为0。只有设为1时才记录暂停请求、保存续扫地址或接受暂停/续扫；生产S3显式传0，启用专项显式传1。S4接入调度时需同步打开此参数并重新验证。

| 信号 | 含义 |
|---|---|
| `scan_pause_request` | 扫描期间申请暂停，可为单拍；扇区处理中会记住请求 |
| `scan_paused` | 当前扫描事务已暂停；只在完整扇区处理后的空闲边界确认，不代表扫描结束 |
| `scan_resume_sector` | 已保存的下一扫描扇区，只在暂停确认时用于读取续扫位置 |
| `scan_resume` | `ready && scan_paused` 时发一拍，恢复保存位置；先撤销暂停请求 |
| `scan_found_total` | 累计发现数量，暂停和中间加载不清零 |
| `scan_done` | 仅代表目标数量或扫描范围真正结束 |

扫描上限和目标数量在同一轮扫描及暂停期间保持不变。图片索引仍按已有 `scan_found_valid/sector/total` 语义记录。当前扇区的头部验证、候选计数和快跳计算先完成，再保存下一地址；不丢弃刚读完的扇区，不回到扫描起点。

`scan_found_valid` 发出后的低读请求边界也可接收暂停请求。S4可用组合逻辑从发现事件提出请求，在下一时钟边沿暂停，无需先读下一扇区。若该扇区已经满足目标数量或范围结束，结束优先，不再产生暂停。

暂停后解析器回到 `ready`，可接受原有 `load_start`，执行真正的头部解析、写应答、像素读取及完成检查。`scan_paused` 在加载中仍表示扫描事务暂停，此时 `ready=0`，不能将它解释为整个解析器空闲。加载复用读地址，但不改保存的续扫地址和扫描累计数量。加载成功或格式失败返回 `ready` 后均可续扫；通信超时仍走既有 STOP 和复位恢复流程。

空闲命令优先级为新扫描、加载、续扫；调用方一次发一个事务命令。新扫描覆盖旧扫描上下文；解析器复位和SD初始化撤销会清除暂停上下文。无需为暂停等待新增自动复位或超时机制。

## 验证

`diagnostics/uart_fastboot/tb_scan_resume.sv` 使用同一原始扇区图谱对比连续扫描与暂停/加载/续扫：扫描读取地址必须同为 `0,1,2,4,5,6`，图片位置同为 `1,4,6`，总数3。中间包含普通空扇区、有效BMP、跨两扇区的可信不支持BMP和格式错误扇区。

- 扇区中单拍请求直到边界才确认；发现事件引起的请求不会额外读取下一扇区。
- 暂停期间加载真实4×2图像，核对8个像素与成功完成，再注入坏头验证失败后仍能续扫。
- 比较所有扫描读取地址、发现数量和位置，检查不漏图、不重复读取。
- 目标数量结束、普通范围结束及快跳恰好达到边界时只结束、不假暂停。
- 暂停超过无进展期限仍保持空闲；新扫描和复位清除暂停事务。

生产640×480解析继续由既有BMP及异步交接回归覆盖。S4启用调度时再按计划补完整640×480端到端验证。

## 构建与备份

隔离构建保留完整输入快照在 `diagnostics/output`；releases仅保存相对S2已验收基线修改/新增的代码、bit、报告和验证日志。`CHANGES.txt`列出基线和覆盖路径；未改动代码、工程及约束从基线取得。候选目录使用 `-text` 保留文件原始字节，入库后逐字节核对。
