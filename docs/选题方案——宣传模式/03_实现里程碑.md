## 1. 版本、基线与执行约定

M0 核实并固定硬件输入为 `v0.17.0-m6-local.1`（`2c78c3a`）；当前 M6 尚待整机板测，不能称为已验收正式 v0.17.0。新功能使用 `v0.18.0` 和 `feature/science-publicity-mode`，分支从文档备份 e71f86a 建立，生产文件与 M6 标签相同。

M0 开始时重新读取项目 `执行规则.md` 和 `HANDOFF.md`：若 v0.17.0 已正式发布，优先固定正式版为新基线；若仍未发布，经当次用户实施指令允许，可从明确的 M6 local 候选启动，单独记录前序未验收项，不替前序发布补结论。正式回退暂为 `v0.16.0`，M0 再核实。

所有开发在原项目目录的功能分支进行，不新建 worktree，不启用子代理，不覆盖个人记录、旧候选、TD 用户状态或素材。中文 UTF-8，生成器输出到新目录，不写哈希，不批量删除文件。

标签约定：M0 对应 `v0.18.0-plan.1`；后续 `v0.18.0-plan.N`、`v0.18.0-mN-local.K`、`v0.18.0-mN-board.K`；最终正式版 `v0.18.0`。M1–M6 标签尚未建立。模块验证或纯 PC 工具阶段无生产 bit 时只提交，不建立 local/board 标签。

本地候选门槛为专项、受影响回归、完整 TD bitgen、无 ERROR、最终 Setup/Hold 为正且 TNS 为 0。用户确认具体候选上板结果后才建立 board 并按规则推送分支与对应标签；修复增加候选编号，不移动旧标签。

## 6. M3：KEY4 双应用切换与静态宣传翻页

**目标**：在同一张卡上安全切换两应用，宣传支持双向四页切换，情景功能可回归。

**实施步骤**

1. 把 app_mode 与 ui_page 分开；去掉“拨码离开 00 就清除场景身份”的耦合，以事件请求代替按键模块直接修改整个应用状态。
2. 实现技术方案 §4 的停止请求、淡出、停止音频、缓存失效、装载首图、帧边界提交和淡入事务。仅复用四 bank，防止 EDU1/PIC1 同号误命中。
3. 宣传 KEY1 上一张、KEY2 短下一张；KEY4 短 AUTO 事件保留，但此阶段宣传 AUTO 明确暂不启用，不能用旧三秒定时器临时替代。
4. 场景 KEY1 短预警/长速度、KEY2 下一阶段/长重扫、KEY4 短 AUTO 保留。跨应用默认第一页、AUTO 关闭、非预警；公共参数保留。
5. 在宣传旁路灾害和场景文案，保证视频流水拍数一致；加载期间屏蔽错误模式标题和旧缓存像素。
6. 加载失败、超时和取消有明确出口；目标不完整时保持当前应用；重扫/复位遵循启动规则。
7. 专项覆盖按键阈值、持键跨拨码、切换中输入、迟到写入、预警退出音频、缺目标资源及旧卡 COMPAT。运行缓存、转场、场景、PCM、预览及生产顶层回归，完整 TD。
8. 形成 `v0.18.0-m3-local.1`，交用户验证同卡切换、两向翻页和情景回归；说明讲解与宣传 AUTO 待 M4。

**验收**：应用身份不随参数页丢失，无混帧/串素材；模式切换不等于全局复位；四 bank 资源仍受控；合格 bit 与源码固定。

## 7. M4：逐页音频、自然结束与宣传轮播

**目标**：完整实现“一页一段讲解”，AUTO 等讲解结束后再翻页。

**实施步骤**

1. 为 PCM 流增加单次/循环控制，宣传 VOI 单次播放，情景/兼容 BGM 保持原循环策略。
2. 在实际样本消费侧记录会话版本和样本数；将读完文件、FIFO 排空、正常消费完成、取消和错误分开。最后一个样本未输出前不能宣布播放完成。
3. 扩展公共音频会话：淡出、停止/排空、更新页音频、首样本确认、淡入；没有 VOI 或读取失败不能阻塞新画面。
4. 宣传翻页后从头播放一次；播完静音保图。AUTO 以“完整画面至少 5 秒＋有效讲解完成”为门槛，缺失/错误按五秒回退并显示真实状态。
5. KEY4 短按 AUTO，关闭只停止后续自动翻页；手动翻页优先并重置计时。参数/预览页不推进，但完成事件持续锁存。
6. 补短讲解、长讲解、无 VOI、奇数长度拒绝、音量零、消费者反压、旧会话 EOF、切预警警报再返回等用例。逐样本比对完整输出，包括句尾非零样本。
7. 回归已有 PCM、SND/BGM 回退、fade、情景终态 AUTO、预览重扫及生产双模式顶层，完整 TD，固定 `v0.18.0-m4-local.1`。

**验收**：四页与讲解严格对应、一次完整播放、自动切页不抢讲解、不死等、不改变音高；缺音频和故障状态可解释。

**会话启动提示**

## 9. M6：内容审定、整机验收与发布

**目标**：将正式科普内容、实际板测数据和已验收 bit 一起交付。

**实施步骤**

1. 再核四页内容出处、图片权利、讲解稿与录音，替换所有占位素材；正式科普内容人工确认，版本和来源归档。
2. 固定双模式整卡与正式讲解、短讲解测试卡、旧卡回退材料；交付候选 bit 和精简验证证据。内容变化也需重新核对音频长度、版式和图音配对。
3. 用户验证四页双向循环、讲解完成后 AUTO、长按模式切换、参数页返回、预览、预警/速度、重扫和旧卡。

## 10. 关键风险及处理顺序

| 风险 | 最早处理阶段 | 处理依据 |
|---|---|---|
| 旧扫描提前结束，宣传资源漏扫 | M2 | 把 EDU/VOI 放在目录末尾验证 |
| 同页号缓存串用 | M3 | 资源身份、失效与迟到请求测试 |
| 拨码调参导致退出情景 | M3/M5 | 应用身份独立，按住键跨页必须重新释放 |
| 读完文件但句尾仍在 FIFO | M4 | 实际消费样本数与最后样本比对 |
| 音量零或缺讲解导致 AUTO 卡死 | M4 | 进度不依赖幅值，缺失/错误可结束 |
| 场景速度条覆盖参数 | M5 | 最终生产 HDMI 像素验证 |
| 新功能影响旧场景终态 AUTO | M4/M5 | 两种 AUTO 门槛隔离，保留终态完整帧测试 |
| 时序无法收敛或资源超预算 | 每个生产候选 | 查最终报告，优化相关小范围后递增候选 |
| 科普内容与配音不一致 | M1/M6 | 来源登记、逐页人工审阅和完整听审 |
