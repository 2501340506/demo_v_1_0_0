## 1. 已核实的现状与改造重点

下表记录 M0 核对的输入基线；scanner/reader 的 M2 实施结果见 §3.2 及接口清单，M3已启用生产入口；基线行为与本轮结果须区分。

| 现有模块 | 当前行为 | 本期改造 |
|---|---|---|
| `SD/mode_key_control.v` | 00 中 KEY4 长按进入/退出场景；离开 00 强制清除场景 active | 应用身份与拨码页解耦，长按输出模式切换请求 |
| 同上 | KEY4 短按 AUTO；情景 KEY1 长按调速、短按预警 | 保持手势，增加宣传上一张路由 |
| `SD/switch_mode_control.v` | 同步并消抖 `{SW2,SW1}` 两位整体 | 继续复用，不直接把异步拨码送入状态机 |
| `adjust/media_adjust_control.v` | 01 默认亮度、10 默认对比度，KEY4 在当前画面参数与音量间切换 | 保持取值和手势，跨应用保留参数 |
| `adjust/adjust_osd_overlay.v` | 场景速度显示会覆盖同一条 B/C/V 显示区域 | 参数页优先显示 B/C/V，速度另区显示或只在 00 显示 |
| `SD/fat32_volume_scanner.v` | 识别 PIC、SND、BGM、FONT、TEXT，已有资源齐全可提前结束 | 新增 EDU/VOI 元数据，并修改提前结束条件 |
| `SD/sd_card_bmp.v` | 四 bank、场景与普通播放器竞争请求，SND 缺失逐槽回退 BGM | 增加应用资源集、切换事务和宣传控制器 |
| `audio/fat32_pcm_stream.v` | 校验零长度、奇数字节长度等，现有流用于循环音频 | 为宣传增加单次播放和可辨识的正常结束事件 |
| `scene/scenario_audio_control.v` | 停止/排空后切换文件，新会话首样本或错误完成握手 | 抽取或扩展为两模式可复用的音频会话控制 |

| `top_tf_hdmi_audio.v` | 32 位像素、灾害图层、调节、转场、OSD、HDMI PCM | 接入应用状态，宣传时旁路灾害与场景文字 |

现有“普通图片播放”可作为宣传播放的基础，但当前 BGM 循环和三秒 AUTO 不能直接当作“每页对应讲解播完后切换”。这部分必须新增完成判定。

## 2. 总体架构与状态划分

```text
FAT32 根目录扫描
 ├─ 宣传元数据：EDU1–4 / VOI1–4
 ├─ 情景元数据：PIC1–4 / SND1–4 / FONT / TEXT
 └─ 兼容资源：PIC1–4 / BGM
                │ 按当前资源集映射到四槽接口
                v
         现有 BMP 解码、缩放、四 bank SDRAM
                │
     宣传：RGB ──┤  情景：RGB＋T → hazard_layer
                v
       亮度/对比度 → 转场 → 参数/状态/字幕 → HDMI

按键/拨码 → 事件路由 → 应用切换管理器
                       ├─ publicity_control：四页、AUTO、讲解完成
                       └─ scenario_fsm：四阶段、终态、预警、速度
                                  │
                    共用音频会话、淡变、PCM FIFO、主音量
```

### 2.1 三类状态分别保存

- `app_mode`：`PUBLICITY` 或 `SCENARIO`。应用切换成功时更新，拨码变化不改写。
- `ui_page[1:0]`：消抖后的 00/01/10/11，对应播放/亮度/对比度/预览页。
- `resource_set`：当前缓存属于 `EDU` 还是 `PIC`，另带兼容标志和有效版本。应用身份与缓存归属在切换提交前不能混为一体。

只有拥有当前资源集的播放器可以提交画面和音频请求。切换管理器优先于两个播放器，避免原普通 AUTO、宣传 AUTO 和场景 AUTO 同时推进。

### 2.2 确定的交互策略

1. 播放页 KEY4 长按 ≥1 秒请求另一应用，短按松开后才发 AUTO。长短互斥，持续按住不重复切换。
2. 切应用从目标第 1 页/阶段开始，AUTO 关闭，情景预警清除；亮度、对比度、音量和情景速度保留到复位。
3. 01/10 调参不会退出当前应用；11 为当前资源集预览。KEY4 在这些页不切应用。
4. 非 00 页面冻结自动翻页/阶段推进。音频继续，宣传讲解完成锁存；情景动画可继续发展到终态并保持。回到 00 后宣传重新计 5 秒，情景重新取得完整终态帧后才允许自动推进。
5. 切换拨码或应用过程中，正在按住的键必须释放后重新按下才有效。清除旧手势计数和未提交的翻页请求。
6. 正在转场时最多保存一个手动翻页请求，不积累长队；KEY4 长按模式请求可等待当前事务安全结束，进入模式切换后忽略新播放请求，并显示 BUSY。

## 3. 文件协议、资源发现与旧卡兼容

### 3.1 双模式卡根目录

| 文件 | 作用 | 资源集 |
|---|---|---|
| `EDU1.BMP`–`EDU4.BMP` | 四张专业科普页 | 宣传 |
| `VOI1.PCM`–`VOI4.PCM` | 逐页讲解，缺某槽时该页无讲解 | 宣传 |
| `PIC1.BMP`–`PIC4.BMP` | 现有四阶段 RGB＋T 图片 | 情景，保持原格式 |
| `SND1.PCM`–`SND4.PCM` | 现有阶段音效/警报 | 情景 |
| `FONT.BIN`、`TEXT.BIN` | 现有情景中文字库与分段文案 | 情景 |
| `BGM.PCM` | 旧卡背景音乐及现有情景逐槽回退 | 兼容 |

文件名全部使用大写 FAT 8.3 短文件名，无子目录依赖。不重新解释原 PIC/SND 的含义，不用同名文件覆盖宣传与情景资源。

宣传 BMP 优先固定为 640×480、24bpp、BI_RGB，加载后 T=255。若工具允许 32bpp 宣传输入，统一写 T=255；宣传显示仍必须从逻辑上关闭灾害图层，不能只依赖像素值。

VOI 固定 48kHz、单声道、s16le 裸 PCM，无 WAV 头。每样本两个字节，文件长度必须非零且为偶数。新制作工具检查格式和长度；硬件流错误保留错误码，不能把读取错误当作正常 EOF。

### 3.2 扫描器与元数据

M2执行结果：默认SCAN_PUBLICITY=0，启用后扫描至根目录零项或链尾；EDU/VOI原表传至reader，新增map_start复用两表预检，EDU固定原槽、PIC保留压缩索引。首次满足簇号/大小基本条件的项占槽，BMP头另作预检，后续同名项不替换已占槽。M3生产sd_card_bmp已开启双表及安全重载，VOI仍未播放，见[M2验证](../../diagnostics/publicity_mode/M2_VALIDATION.md)。下文为总体要求。

新增 `edu_valid[3:0]`、四槽 EDU cluster/size、`voi_valid[3:0]`、四槽 VOI cluster/size。沿用已有资源表风格，无须为八张图增加八个像素缓存。

重点核查扫描结束条件：现有 PIC/SND/FONT/TEXT 齐全不能提前结束，否则目录靠后的 EDU/VOI 会漏扫。双模式扫描须持续到根目录结束、目录链结束，或全部启用资源均齐全；可选资源缺失也必须正常结束，不能死等。沿用既有最大遍历限制。

使用独立槽 valid mask；“找到 3 个文件”不能推定为“第 1–3 槽齐全”。重复短文件名沿用首次有效项规则，不增加动态排序。检查文件属性、簇号、大小及既有目录项流水提交对齐。

### 3.3 可用性与启动规则

| 卡内容 | 开机行为 | KEY4 长按 |
|---|---|---|
| EDU 四图齐全、PIC 四图齐全 | 宣传第一页，AUTO 关闭 | 在两应用间切换 |
| EDU 四图齐全、PIC 不齐全 | 宣传第一页 | 提示情景资源不全，保持宣传 |
| 无 EDU 或 EDU 不齐全、有可播放 PIC | 兼容普通图片播放，明确标识 COMPAT，沿用 BGM | PIC 四图齐全时允许进入情景，再次长按返回兼容播放 |
| 没有可播放图片 | 显示原错误/无资源状态 | 不启动切换，允许既有重扫/复位恢复 |

正式双模式包要求 EDU 四图完整。零散 EDU 文件不参与兼容图片列表，也不与 PIC 混组；现有旧卡不足四图的普通播放能力继续保留。VOI 缺失不会禁止宣传，但应显示 `NO VOICE`，采用 5 秒停留回退，不能用 SND4 警报冒充讲解。

## 4. 四 bank 缓存与应用切换事务

### 4.1 复用方式

当前四个 640×480×32bit bank 共 4,915,200 字节。新版本仍只缓存当前应用四张图；SD 上可有八张图，SDRAM 不要求同时保留八张全屏图。

EDU/PIC 元数据通过映射选择器送入现有四槽加载接口。缓存有效状态必须携带资源集身份；切换时失效旧映射、cache_valid、失败记录、预取和预览描述，防止相同页号误命中另一模式。

### 4.2 建议状态机

| 状态 | 行为 | 退出依据 |
|---|---|---|
| IDLE | 接受模式切换请求，预检目标资源完整性 | 请求合法且目标可用 |
| QUIESCE | 禁止新播放请求，等当前画面事务完成，取消/排空旧预取 | 存储事务结束或取消确认 |
| FADE_OUT | 淡出当前画面和音频 | 黑场确认、静音确认 |
| STOP_AUDIO | 停止流并排空旧 FIFO，保留切换目标 | `audio_stopped` |
| INVALIDATE | 更换资源映射，清空旧缓存有效位，更新资源版本 | 旧请求已全部回收 |
| LOAD_FIRST | 装载目标第 1 张，必要时载入情景 FONT/TEXT | 首图加载成功与资源就绪 |
| COMMIT | 帧边界提交新 bank 和显示身份，启动对应音频会话 | 显示提交确认及音频就绪/缺失/错误可结束状态 |
| FADE_IN | 新画面与音频淡入 | 转场完成 |
| RUN | 提交 app_mode，复位目标页计时及 AUTO，后台补齐其余图 | 返回 IDLE |
| ERROR | 显示明确错误、停止 AUTO，支持重试或切回可用资源 | 用户重扫/切换/复位 |

提交前使用 `target_mode` 驱动目标素材与淡入画面，不能提前让旧控制器看到新的 app_mode 并发起请求。跨时钟域的显示元组必须包含目标应用身份和资源版本。

资源预检失败时不破坏当前画面。开始覆盖 bank 后发生实际读卡/解码失败，不承诺立即恢复旧四图；停留在受控错误画面，按目标元数据重新装载或重新装载原应用。严禁把部分加载的 bank 标成有效。

所有等待沿用或补齐既有超时/错误出口；超时退出须先取消并确认旧事务结束，不把未完成写入交给另一资源集。重扫使旧资源版本失效，任何迟到结果都不能提交。

### 4.3 切换时不必物理重扫卡

应用切换可复用启动时已扫描的两套元数据，执行逻辑缓存失效和装载；不应为了切应用重置整个 SD SPI 协议栈。KEY2 长按重扫仍走独立恢复流程，重扫后按启动规则选择模式，AUTO 关闭。

如复用现有 cache 的重扫入口实现映射刷新，须区分“重读目录”和“更换四槽资源表”，避免无意清空已发现的另一套资源。不得直接连全局复位模拟应用切换。

## 5. 宣传播放控制与音频完成

### 5.1 宣传控制器接口建议

```verilog
// 示意接口，实际实现按现有握手风格调整。
module publicity_control (
    input clk, rst, enable, ui_play,
    input previous_event, next_event, auto_toggle_event,
    input frame_tick, display_committed, picture_failed,
    input request_ready, transition_idle,
    input voice_available, voice_started, voice_done, voice_error,
    output reg [1:0] page,
    output reg auto_enabled,
    output reg picture_request,
    output reg [1:0] requested_page,
    output reg voice_request,
    output reg fade_mute
);
```

页号内部为 0–3、显示为 1–4。仅在画面提交确认后修改当前页号，讲解选择使用已提交页或同一事务目标，不能使用正在消抖的按键直接选择文件。

计时从新页完整呈现、淡入结束后开始。按既有约 60 帧/秒定义 5 秒为 300 个帧 tick，并在验证中记录实际时钟口径。参数/预览页不累计本次返回后的最短停留；静音不影响计时和讲解进度。

宣传 AUTO 推进条件：

```text
auto_ready = PUBLICITY && AUTO && ui_page==00
             && page_fully_visible && min_dwell_done
             && (voice_done_latched || !voice_available || voice_failed_latched)
             && !transition_busy && !mode_switch_busy
```

`voice_error` 允许该页按无讲解回退继续轮播，但必须显示错误状态；不能伪装成“完整讲解已播放”。新页提交时清除上一页完成/错误锁存。没有音频或开始失败时不等待永远不会出现的 `voice_started`。

### 5.2 单次讲解与自然 EOF

现有背景音频自动循环，必须增加显式单次播放策略，例如 `loop_enable`：宣传 VOI=0，情景音效和旧 BGM 保持原循环策略。不能只在文件流取完最后扇区时立即报告讲解完成，因为 FIFO 和 HDMI 链路中仍有音频样本。

建议在消费者时钟域统计本次会话实际 `valid && ready` 接受的源样本数，以 `sample_total=file_size>>1` 判断最后一个有效样本。文件源读到 EOF 后停止本次再次启动，待缓存排空和最后样本被接受后锁存自然完成；必要的 FIFO 写侧 EOF 标志通过稳定握手传递。

统计点在主音量缩放前，覆盖音量 0、HDMI 反压与暂停供数；不得根据样本幅值是否为零判断“无音频”。帧侧动作还需覆盖 HDMI 内部固定延迟，至少在后续安全帧边界才执行自动切换，并用实际输出样本验证没有切掉句尾。

正常 EOF、用户取消、读取错误分开报告。手动翻页的取消事件不能变成新页的正常完成。每次讲解从文件头重新开始，包括上一张、下一张和从预览提交同一页。

### 5.3 会话身份与跨域

模式、页号和会话版本随音频请求一起锁存。先停止旧流并确认 FIFO 排空，再更新元数据并启动新会话；旧会话的 `started/done/error` 在切换后不得命中新页。

跨域使用项目已有 mailbox/请求应答和 Gray 样本计数模式。多位参数不能逐位双触发同步；完成脉冲不能只打一拍跨域。事件需锁存到应答或用带版本的 toggle 握手；复位时统一清理双方会话状态。

### 5.4 音频选择与画面转场

| 情况 | 音频策略 |
|---|---|
| 宣传有对应 VOI | 该 VOI 从头单次播放，完成后静音 |
| 宣传缺 VOI | 静音＋NO VOICE，AUTO 用最短停留回退 |
| 宣传 VOI 损坏/读取失败 | 停止本会话、报告错误，再按无讲解回退 |
| 情景有对应 SND | 沿用对应阶段音频 |
| 情景缺该 SND | 保持既有逐槽 BGM 回退及后续无音频语义 |
| COMPAT 普通图片 | 保留 BGM 循环，不重写成宣传讲解语义 |

翻页/切模式沿用 `pcm_master_volume.fade_mute`。先淡出并停止旧流，新画面提交且新会话首样本就绪后淡入；无音频或失败应有可结束握手，不能让视频卡死。音量调节只改变增益，不改变 48kHz 输出速率。

## 6. 参数页、OSD 与预览

M5已按本节整合验证，修正情景11焦点路由和提交事务；实际仅改三个生产文件，见[接口清单M5节](../宣传模式接口清单.md)及[M5验证](../../diagnostics/publicity_mode/M5_VALIDATION.md)。

### 6.1 参数通路

沿用 `media_adjust_control` 的 B/C/V 状态、默认值和步进。`media_adjust_cdc` 继续以稳定元组在帧边界提交，主音量和画面使用同一帧参数。无需为两个应用分别复制参数寄存器。

01/10 参数页始终显示 B/C/V 真实值和选中项；情景速度提示不得覆盖它们。00 情景页可以显示 SPEED；00 宣传页显示 `EDU 1/4`、AUTO 和讲解状态。模式标题可用固定 ASCII 标识，科普中文正文已烧入图片，避免扩充 TEXT.BIN 协议。

不新增宣传调速键。上一张、下一张、AUTO 的行为不会被调速替换；情景速度保留 KEY1 长按一秒，只作用于情景动画。

### 6.2 视频流水

宣传关闭 `hazard_layer`、场景标题/村名/字幕、红框及预警字，但保留必要状态、UART、参数条和音频可视化。图层旁路保持原流水拍数，RGB、de/hs/vs、坐标、bank/应用描述全部对齐。

帧边界一起提交 `{app, resource_version, bank, page, overlay_enable}`；不能在一帧中途把图层或标题切到新模式。场景 BRAM 字库读延迟保持现有约定，返回情景前确认字体/文本已有效。

### 6.3 缩略图

11 仅预览当前资源集。宣传预览画面不播放焦点页讲解；沿用当前页音频，KEY4 短按成功提交后才切换讲解。参数/预览期间 `voice_done` 仍记录。

模式切换前必须退出预览事务并清理旧描述；新资源集未载入的 bank 显示无效占位，不能显示旧应用缩略图。情景的预览选中行为须回归，不在本期扩展预警/速度手势到 11。

## 7. 离线科普包工具

M1已新增 [tools/make_publicity_pack.py](../../tools/make_publicity_pack.py)，标准WAV提取与原工具四槽逐字节对照通过，BMP独立反读通过。实际配置见 [pack.yaml](../../tools/publicity/geohazard_basics/pack.yaml)，使用说明及限制见 [内容包README](../../tools/publicity/README.md)。下例仅列第一页，其余须按2/3/4补全；实际输出由命令行 `--output` 指定不存在的新目录。

```yaml
version: 1
name: 地灾科学避险科普
content_version: draft.1
pages:
  - id: 1
    title: 认识常见地质灾害
    image: inputs/page1.png
    audio: inputs/page1.wav
    audio_status: narration_unreviewed
    script: scripts/page1.txt
    source_refs: [sources/source01.md]
  # 其余三页同结构，id 按 2、3、4 排列
```

工具要求恰好四页，音频可显式为空以制作缺讲解测试包。正式内容包要求四段讲解齐全。输出 EDU/VOI 文件、四页预览和 manifest；manifest 记录原始来源、页号、文件字节数、PCM 样本数/时长、格式和内容版本，不写哈希。

默认只导出宣传资源，不复制或覆盖情景同名文件。双模式整卡打包脚本从明确的两套输入目录合并到新的输出目录，校验无冲突后附整卡清单。对既有交付文件做大小与逐字节比较，所有生成器拒绝覆盖已有输出。

Python 用 `py -I -X utf8`。先验证现有标准 WAV 直接提取路径；其他采样率或 MP3 需要 ffmpeg 时核实本机工具存在并单独验证，不能把未跑过的转换链写成可用。依赖沿用 Pillow、numpy、PyYAML，按实际脚本最小化。

M1实际实现严格接收640×480不透明RGB图和48kHz/mono/s16未压缩WAV，不做隐式缩放/重采样，其他音频格式明确拒绝。音频可为test_tone或narration_unreviewed，工具不认证正式配音；显式null须配missing并省略该槽PCM。当前四段为2/6/8/10秒测试音，画面/清单均标识非正式配音。16项PC测试、14个产物新目录逐字节复现及9个输入重生成通过，见[M1验证](../../diagnostics/publicity_mode/M1_VALIDATION.md)。专业审阅、录音与听审/HDMI仍待完成；本阶段无bit/local/board标签。双模式整卡合并尚未实施。

## 9. 验证策略

### 9.1 专项仿真与 PC 自检

- 按键：KEY4 一秒阈值前后、持续按住、释放、拨码切换中按住、忙状态；长按不触发 AUTO；宣传上一张和情景预警/速度不串路由。
- 扫描器：两套文件在根目录任意顺序、EDU/VOI 在旧资源之后、跨扇区目录项、缺可选文件、缺中间槽、重复项与旧卡。
- 缓存：同页号跨资源集失效、迟到加载结果、取消/超时、切换期间重扫、未完成图不提交、预览不会命中旧资源集。
- 宣传控制：首图提交后计时、5 秒下限、音频长于/短于下限、无讲解、错误、AUTO 开关、手动与自动同拍、非 00 完成锁存及返回重计时。
- PCM：从实际消费者输出逐样本比对，覆盖 FIFO 余量、最后非零样本、音量 0、反压、短文件、奇数长度拒绝、取消后旧 EOF、两模式连续往返。检验一次讲解恰好消费 `size/2` 个源样本。
- 视频：使用可区分的 EDU/PIC 像素图，对最终生产顶层输出验证应用身份、bank、页号、图层使能及帧边界；检查参数/速度条不互相覆盖。
- 工具：输出命名、BMP 反读、PCM 样本数、图音配对、拒绝覆盖和在新目录逐字节复现；正式讲解稿与音频须人工听审。

### 9.2 回归与物理构建

修改点专项通过后，回归原 24/32bpp 解码与缩放、四 bank 缓存、转场、预览重扫、PCM、FONT/TEXT、UART 及原整机长回归。加入真实生产顶层双模式整卡用例，不能只用不例化新模块的旧测试台证明通过。

TD 使用项目既有构建与审计流程，检查实际最终资源和 Slow/Fast 时序报告、覆盖率、约束及告警差异。保存失败尝试，合格候选固定 bit、变化源码、工程输入清单和精简证据；比对用字节，不写 SHA256。

### 9.3 板测

验证宣传四页及讲解、双向翻页、AUTO、拨码参数、预览、两模式往返与情景旧功能。至少 40 分钟连续运行，含多次切模式；记录 Flash 完全断电到首个完整宣传画面，以及 KEY4 达长按阈值到目标首个完整画面的耗时，按两个方向分别测量。

记录缺图/坏 VOI/旧卡恢复，换卡后复位计时。板测次数、秒数和单项结论只取用户实际反馈，不能用仿真帧数、旧 M6 数据或目标估计代替。

## 10. 已定设计决策

| 决策 | 本期方案 |
|---|---|
| 应用入口 | 00 下 KEY4 长按 ≥1 秒，宣传 ↔ 情景；短按始终 AUTO |
| 参数入口 | 01 亮度/音量，10 对比度/音量；应用身份保持 |
| 宣传素材 | 四个 EDU BMP＋四个 VOI PCM，图片内含正文 |
| 存储 | 同卡八图资源、运行时仍复用四 bank，跨模式重载 |
| 宣传 AUTO | 5 秒最短停留＋有效讲解自然播放完成，缺失/错误有回退 |
| 音频结束 | 单次会话、实际消费样本完成，正常/取消/错误分开 |
| 情景 AUTO | 保留动画终态及完整帧门槛，与宣传计时隔离 |
| 模式切换后 | 目标第一页、AUTO 关闭、非预警；公共参数保留 |
| 参数存储 | 仅会话内保留，复位恢复默认，不新增 Flash 保存 |
| 旧卡 | COMPAT 普通播放及原情景入口保留，不能冒称专业宣传包 |
| 热插拔 | 换卡后复位，不把重扫等同于物理协议热恢复 |
