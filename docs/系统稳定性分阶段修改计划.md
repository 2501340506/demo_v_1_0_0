# v0.4.0 系统稳定性增强分阶段方案

2026-10-05。基线：main / v0.3.0；开发分支：feature/system-stability-v0.4.0。

## 目标与范围

完成课程五项必做：BMP头校验、错误上报与有限恢复、坏图快速跳过、加载超时、像素完整性检查。保留640×480、24位未压缩、正高度BMP、原始连续扇区读取、双缓冲及现有音视频功能。

参考配套bmp24_decoder的校验/提交和media_recovery_fsm的有限重试思路，不整体移植文件流接口、缩放或扩展架构。不修SD初始化、命令响应和热插拔恢复；不引入快速启动、Flash配置、UART、OSD或参数集中化工程。

## 接口与行为

- bmp_read新增单周期load_done/load_error和bmp_error[2:0]：0正常、1头错误、2超时、3像素不完整；扫描超时使用独立scan_error。
- 上层锁存任务结果；只有加载成功和本次写完成同时满足才发起显示提交。失败不切换显示缓冲、不更新编号、不发音频事件。
- 已结束事务的头错误/不完整像素重试同图一次。MAN再失败保持旧图结束请求；AUTO继续下一候选；首图顺序尝试后续候选。
- 每轮最多遍历候选表一次，全失败停止自动加载。已有画面允许新手动请求重试；无首图全失败等待复位。末位E/F/d表示头错误/超时/不完整，直到成功显示或复位；正常显示图片编号。
- 尺寸完整32位比较，拒绝负高度；DIB>=40、planes=1、像素偏移不早于DIB末尾、声明长度容纳预期像素；计算保留足够位宽。
- 快跳仅用于长度和结构可信、跨度有效且在扫描范围内的BM候选，否则+1。不承诺MP3等非BMP快速跳过。
- 640×480每行1920字节，无行填充；成功输出307200像素，忽略附加尾数据。有结束但少字节为不完整，无响应为超时。
- 重试使用未显示缓冲及新写请求清FIFO；验证旧写完成事件不污染新任务。
- 超时默认100MHz/500ms，按单次等待或无进展计时，有效数据/新事务重新计时；先除后乘换算，仿真可缩短参数。
- 未结束SD事务超时撤销BMP请求、屏蔽像素、禁止新加载/提交，锁存错误等待复位，不盲目重试。
- 原始扇区接口没有真实文件EOF；截断文件仍读到足量旧数据不能检测。像素数量不等于文件内容完整性。
