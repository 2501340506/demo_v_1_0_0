# v0.7.0：8890 LUT 组成与缩减方案

日期：2026-10-08。本次只分析报告和 RTL，未修改生产 RTL、重新综合或改动验收 bit。

## 基线与统计口径

依据 releases/v0.7.0/s3-local.1/reports/demo_phy.area 和 final_timing.rpt，对应 fat32_s3_attempt7。当前 UART、FAT32 scanner/streamer/reader、BMP decoder/header、SD 包装器及顶层八个文件与该构建快照逐字节一致。

LUT 8890 / 19600（45.36%），寄存器 5686，BRAM9K 4 / 64，DSP 2 / 29。Setup +0.104 ns，Hold +0.014 ns。

层级表 lut=7517 加 ripple=1373 正好为 8890。以下统一用 lut+ripple；le 不是 LUT。父层包含子层，不可重复相加。

## 优先方案一：UART 字符生成

uart_event_logger.v 先选择 80 位事件名称，再动态取字节；时间、扇区、debug 也通过动态 part-select 取十六进制字符。动态选择和索引运算值得优先局部综合。真正 uart_tx_byte 仅占 42 LUT，主要开销在外围。

- 事件名改为以事件编号、字符位置寻址的 8 位 ROM，比较逻辑 ROM 与 BRAM ROM。
- 时间、扇区、debug 共用字段装载、固定高四位输出和移位通路，减少多套动态选择器。
- 第一轮保持日志格式、8 深度队列和丢弃计数行为，用现有 UART 仿真逐字节比较。
- 第二轮再评估 BRAM 队列。综合日志明确记载 queue 为 8×154 的分布式 RAM，并非 1232 个 FF。154 位并行口可能需多块 BRAM；窄口多拍打包必须保持快照一致性及入队能力。不能把整个 1136 LUT 都当成队列，也不能保证单纯减队列深度会省很多。

若允许牺牲串口诊断，可新增编译期开关关闭 logger。按当前模块规模相减，8890-1136=7754，仅作粗略参考；实际综合可能额外裁剪上游诊断逻辑，也会改变映射。默认推荐保留日志功能。

## 优先方案二：共享 BMP 头检查、收紧像素计数

fat32_bmp_reader.v 的 preflight 在扫描时用，decoder 内的 u_header 在加载时用，阶段互斥。可共享一套检查器并把检查结果和元数据交给 decoder；加载时仍重新检查头，不直接信任扫描时旧数据。明确来源选择、复位、header_complete 和流水线结果稳定时刻。

可消除的重复块规模约 287～315 LUT，需扣除新增控制与选择逻辑；不是已测净收益。

bmp24_decoder.v 的 row_byte、row、col、pixel_count 均声明为 32 位。生产固定 640×480、24 位，每行 1920 字节，可考虑 11、9、10、19 位，且要容纳行/像素终值。通用模块用参数推导宽度，保留通用测试能力。综合器可能已裁掉部分高位，收益待测。

文件大小、pixel_offset 和 LBA 保留大地址能力，不随像素计数器一起缩窄。顶层已传入常量 640/480，单改 RUNTIME_DIMENSIONS 不保证收益。skip_format 未接，相关计算可能已被裁掉，不能按 RTL 中乘法表达式数量估算面积。

## 优先方案三：FAT32 多拍共享运算

scanner 含多套布局加减、动态移位、簇转 LBA 和比较；streamer 与 reader 预检也分别实现 data_lba + ((cluster-2) << cluster_shift)。目前分拍改善了时序，但分拍不等于自动复用算术单元。

先在 scanner 内共享临时寄存器/加减器，比较桶形移位和逐拍移位；再视收益决定是否跨 scanner、streamer、preflight 共享地址计算。选择器自身也有成本，避免一开始重写整条链。

cluster_shift 为 0～7；100 MHz 下多 7 拍约 70 ns，16.667 MHz SPI 传 512 字节数据约 246 μs，有以运算延迟换面积的空间。保留握手、超时语义及现有流水线边界。

streamer 的 size_latched-remaining_bytes 可与递增 offset 方案比较，但新增计数器也有成本，不预先承诺。纯簇号可审查 28 位表达，LBA/文件大小仍保留 32 位；常量高位可能本来就已优化。

## 后续小项

scanner 和外围 sd_card_bmp 各保存四组 cluster/size，可评估只保留一份表加有效索引映射，或预检后原地压紧；需保持重扫、加载和旧图显示的上下文。表很小，不优先强行 BRAM 化。

ack_wait 默认 500 ms @100 MHz 只需 26 位，可由参数推导替代 32 位；收益较小。按键、数码管和复位不是第一轮主要目标。

## 路线与预期

推荐顺序：UART 字符生成 → BMP 共享检查及局部位宽 → FAT32 多拍运算共享。每一步独立记录 lut、ripple、寄存器、BRAM、DSP 与时序。

可将降到 8000 LUT 左右作为第一轮工程目标，需要省 890（约 10%），但不是预测值。保持全部功能降到 7000 以下需要净省 1890，目前没有综合证据支持承诺。

验证围绕改动运行现有 UART、BMP 和 FAT32 用例，覆盖格式/队列、预检/加载、最后像素、错误中止、重扫、碎片和大地址；候选最终跑完整 TD 布局布线及对应板测。Setup/Hold 余量较小，不为省资源直接合并流水线。

本次没有 A/B 综合，所有净收益待测。后续构建使用新 diagnostics/output 目录，不覆盖用户 TD 工程、best_result 或发布 bit。
