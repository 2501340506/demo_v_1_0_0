# 缩略图课程与时序余量研究（2026-10-12）

## 范围与基线

本轮仅研究：读取指定第14课 Markdown、同目录四个 Verilog 文件，并对照当前 RTL、实际布局布线报告及《执行规则.md》。未修改生产 RTL、约束或工程，未运行新仿真/构建，不生成候选。沿用当前 feature/image-scaling-thumbnails 分支；起点提交 da25c8d。保留已有两个 SPI 文件及 HANDOFF 的未提交改动、素材、BGM.PCM 删除状态和两个旧 worktree。

结论：有明确的修复路径，优先切断扇区响应的跨模块组合控制链，再处理 BRAM 最短路径。课程可帮助划分控制与显示边界，但直接替换缩略图控制器不能修复当前报告中的关键路径。

## 当前失败路径与具体改法

### 1. 第一优先：文件读取端的扇区响应流水

最新最差路径从 media_frame_load_control 的 state 寄存器出发，经 sd_sector_service 的组合控制/错误选择，到 fat32_file_streamer.sector_in_cluster 的 CE。报告给出 6 级逻辑、10.277 ns 数据延迟，其中 cell 2.495 ns、net 7.782 ns（76%），最大扇出 42。另有 sector_lba CE 失败。这不是缩略图坐标乘法路径。

对应源码链：media_frame_load_control.parser_cancel → fat32_bmp_reader.load_cancel → sd_sector_service.p_cancel/p_error → fat32_bmp_reader.sector_error → streamer 的 ST_DATA_WAIT/ST_FAT_WAIT 分支及寄存器更新。p_error 组合依赖 discard/p_cancel/active/owner；streamer 在响应当拍又决定错误、簇内递增、换簇及地址更新，跨模块布线放大了延迟。

建议首先在 fat32_bmp_reader 的文件读取响应入口，仿照已有 scan_sector_* 流水，寄存 byte、index、valid、done、error 以及所属文件的有效限定，统一延后一拍再送 streamer。保留扫描与音频客户端现有接口，先做最小范围修改。取消时清除本地待交付响应，保持物理读排空和原有取消优先级；不要只延迟 error 或 done，否则最后一个字节、EOF 与错误会错位。

若 CE 链仍长，再让 streamer 在 WAIT 状态只保存结束状态，下一状态做错误判断、簇计数与地址更新。数据最后一字节可能与 done 同拍，remaining_bytes 必须按更新后的值设计，不能机械搬运旧条件。该方案增加的是扇区边界少量时钟，不要求降低 SD/像素时钟；是否影响吞吐由已有图片/音乐并发仿真验证。

### 2. 第二优先：定点修复 BRAM Hold

最新三个 Hold 失败端点：

|报告路径|余量|含义|
|---|---:|---|
|image_scale_nearest.sx → 行缓存 BRAM addrb|−0.012 ns|读地址最短路径|
|pcm_stream_player.wr_bin → 音频 BRAM addra|−0.012 ns|写地址最短路径|
|报告命名 g_audio_vis/u_levels/bar_height_b1 → full_writer/write_buf BRAM addra|−0.004 ns|综合映射后的最短地址路径，不能仅凭起点名字修改圆环模块|

前两条数据延迟仅 0.333 ns，时钟偏斜 0.045 ns。这类问题不靠缩短组合逻辑解决，降低频率通常也不能解决同沿 Hold。

优先核对当前保持修复配置与映射；既有脚本已设置 drHoldFix on，PlaceHoldFix 对应 place fix_hold high，不能把“打开自动修复”当成尚未尝试的新办法。attempt9/10 的结果相同，说明该策略在那一版本没有改善。

若物理策略仍不能收敛，在确切违规 BRAM 地址输入上试验少量保留的恒等 LUT，并检查综合网表确认没有被消掉、实际 Routed min delay 确有增加，同时检查 Setup。不要全总线、全工程撒延迟，也不要声称一颗 LUT 保证多少物理延时。已有 MISO LUT 只证明该历史输入路径能收敛，不等于 BRAM 路径已经验证。

另一种较大改法是利用读写事务间隔，提前准备地址并在访问期间保持稳定；必须连同地址、数据、使能及指针可见性设计，重新验证 RAM 推断与逐样本结果。单纯再加同沿地址寄存器，仍可能出现新寄存器到 BRAM 的同类 Hold，不作为首选。

### 3. 改善收敛后的余量：BPB 校验与局部控制

attempt17 虽通过，最差 Setup 之一是 scanner.root_cluster → sector_lba.ce（+0.117 ns；7 级，9.603 ns，其中布线 6.155 ns）。fat32_volume_scanner 的 bpb_ok 把多项字段检查组合后用于 ZERO_PARSE/BOOT_PARSE，并参与 MBR 地址选择。

可在扇区完整接收后分组寄存 BPB 判定，再在下一状态选择 MBR/BPB 分支；保留末字节 signature 完成后的判定时点。只改变计算时序，不增加检查条目。需要时把 spc 的幂次判定等价改成合法值 case，但不能假定它单独解决 root_cluster 路径。

attempt17 的另一条 +0.117 ns 路径也落到 streamer.sector_lba.ce；这进一步支持先做响应边界流水，而非只更换布局种子。

## 课程可借鉴与不能照搬之处

- thumbnail_controller.v 是空 TODO 骨架，并无可直接集成的已验证实现。
- Markdown 3.2.2 的“参考答案”在按键当拍修改 view_mode/focus_index/active_index，仅 transition_req 等 frame_start；与文中所有显示状态帧边界生效的说法不一致。不能据此替换当前描述邮箱和帧边界应答。
- 课程 media_player_control 的请求/应答及像素帧提交是有用思路。当前 media_preview_control 已有稳定描述、请求翻转和应答同步，实际图像提交与预览描述分开管理，应该保留。
- 课程默认 160×120，四格仅覆盖 320×240 区域；当前需求为四个 320×240 铺满 640×480。课程 integer 坐标和常量比例表达式不必然综合成通用乘除器，不能仅看星号宣称其时序差。当前模块已使用窄位宽和移位。
- 当前紧凑缩略图缓存源自真实 SDRAM 连续 BL4 验证；课程 source_x/source_y 映射不提供适配该突发控制器的存储读取实现，不能为了简化坐标而回退为逐像素跨步读取。
- 本次关键路径不在 focus_index 或 thumbnail_layout；显示流水只在后续报告明确命中时再改，并同步 RGB、DE、HS、VS、边框和坐标延迟。

## 后续实施阶段与验收

1. 固定本轮源码、工程选项和失败报告作为比较基线，保留用户未提交 SPI 改动。新修复在原目录新建 feature/thumbnail-timing-margin；不另建开发 worktree。先明确 SPI 保留当前实现还是单独对比历史实现，不混在响应流水修复中一起改。
2. 仅实施文件响应流水；跑 FAT32 42 项、完整字节流/末字节、真实 SDRAM 双 writer、取消/重扫/失败恢复及图片音乐并发，再完整 TD。必要时进一步分拆 streamer 结束状态。
3. 按新报告处理实际仍存在的 BRAM Hold；仅在需要提高 Setup 余量时追加 BPB 分组寄存。每个改动单独比较，完整 TD 同时检查 Setup/Hold、资源与覆盖。保持现有 SDC，不扩大 false_path/multicycle、不删除默认 uncertainty。
4. Setup/Hold 非负后审计与固定新候选。若继续 v0.14.0 S3，使用下一个未占用 v0.14.0-s3-local.N（当前已有 local.1，实施时再核对编号）；用户确认后才建对应 board.N。建议额外争取 Setup 约 0.5 ns、Hold 约 0.05 ns 的余量作为优化目标，不冒充现有硬性验收规则或达成承诺。

本轮结论属于报告和 RTL 静态研究；上述改法尚未实施，不能记为仿真、TD 或板测通过。当前已有测试足以覆盖主要真实风险，无需为研究另造大批测试。既有报告会被原工程重建覆盖，实施前应保存所需证据到独立诊断输出。
