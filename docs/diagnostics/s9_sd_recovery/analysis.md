# S9复位卡0、拔卡卡2：原因分析与修复方案

最新范围确认：2026-10-05用户确认“S9通过，开始下一阶段，我提到的问题不在这一版本修改，也先不做相应修改”。S9按用户结论验收通过；SD复位偶发卡0、扫描/读头拔卡卡2及连续翻图中复位卡0作为已知问题保留，明确暂不修改。未补造逐项设备、次数或运行时长。 下文为此前分析与未执行建议，不是当前修复任务，也不再阻塞本版本发布。

2026-10-05。用户最新反馈：①每次复位有概率末位一直0；②复位后末位2时立即拔SD卡，末位一直2；③连续下一张未完成时按KEY3复位，有概率出现①（仍为0，不是1）。S9未通过，暂停正式v0.3.0发布。当前仅分析及复现，未修改板级RTL、未生成新bit。

## 状态码含义

正常面板不是独立诊断面板。media_display_control在display_valid=1时显示img_idx+1，即1～4为当前图片；只有首图提交前显示bmp_state_code。bmp_read复位或sd_init_done=0时为0；扫描/读取首图头时为2。因此“复位后首图出现前的2”表示扫描/读头，画面已经显示后的2可能只是第2张图，不能只看数字定位底层状态。0支持初始化未完成的判断，但不能单独排除复位请求/PLL锁定异常。

## 已确认的代码问题

1. `sd_card_cmd.v` S_CMD同时发送6字节命令和判断R1，每次spi_wr_ack都做响应比较，没有限定命令6字节已发完。发送阶段若读回00、残留数据或其他bit7=0字节，会提前判成功/失败。新增字节级仿真以CMD0第一发送字节读回00，复现只发1/6字节就报错。此为真实实现缺陷；板上复位时是否恰好读回该值尚未实测，不把它宣称为唯一根因。
2. S_READ_WAIT只接受0xFE，无计时、失败或退出分支。仿真连续2000次返回FF后仍停留；源码没有任何累计等待上限，因此持续无token时不会自行恢复。
3. 初始化CMD0/CMD8和读命令CMD17虽然底层存在65535字节等待上限，上层对失败继续重发，没有总时限、限次重试、错误通知或重建整条链路。底层“单命令有超时”不等于系统可恢复。
4. sd_init_done在ACMD41成功时就置1，后面CMD16尚未完成；CMD16失败回CMD55时该标志不清零，上层可提前进入扫描。读卡失败/拔卡也没有撤销此标志。
5. bmp_read扫描/读头仅等待sd_sec_read_end，接口没有读失败输入；sd_card_bmp和帧写入也没有跨层的事务取消。这解释为何故障状态没有可见错误或补救流程。
6. 卡在读数据区中途被拔走时，SPI仍会产生字节完成，应答不意味着卡仍存在；现有读取只按514字节计数结束，没有CRC16校验，可能把无效数据当成功，继续扫描或写入。不能把全部FF简单定义为错误，因为合法数据也可能含FF。

## 三种现象的解释

①卡0：最接近“初始化没有走完”。FPGA复位不会断掉SD卡供电；热复位可能打断正在进行的命令/数据事务。命令发送阶段误判响应、没有总时限的重试，以及KEY3未做按键释放稳定/最短复位保持，均是应优先处理的因素。复位三拍同步解决的是时钟域释放，不负责让外部卡事务复原。PLL/复位信号和电气问题仍需对照验证，不能凭面板断言。

②首图前拔卡卡2：上层已扫描/读头，底层可能卡CMD17重试或等待0xFE；初始化标志仍为1，bmp_read收不到完成/失败，数字保持2。若拔卡恰在数据区，可能读入无效字节并继续扫描，外观同样长时间2。当前没有接入卡检测引脚，sd_miso约束PULLTYPE=NONE；需要核对板载外部上拉，不能假定拔卡后的MISO一定为FF，也不能仅靠MISO电平判定卡是否存在。

③连续请求中复位卡0：控制器按方向最多挂起一次，并且复位会清空next_pending/previous_pending、load_busy及提交状态；没有证据支持“按键排队没清空”。连续按键提高SD事务正在执行时遭复位的机会，是外部卡热复位/重新初始化问题的重要复现场景。

上述SD协议逻辑在S8之前已存在；S9改变复位释放时刻，可能改变触发概率，但现在没有S8同操作对照数据，不能说全部由S9引入，也不能因为属于旧代码而不修。

## 建议修复顺序

1. 修正命令事务：分开发6字节与等待R1两个阶段；发命令期间不解析R1。初始化完整成功且读接口可接请求后才置sd_init_done，初始化/读失败清零或发布明确错误。正确结束CS和补空闲时钟。
2. 添加必要的失败路径：命令响应、读token和初始化总时限，有限次数重试；读扇区错误向BMP层反馈。对扇区数据校验CRC16，防止拔卡后假完成进入正常显示提交。计时使用真实时间，正常逐扇区进展应刷新等待计时，不用过短的整张图固定超时。
3. 统一恢复：KEY3异步触发复位，释放要求按键稳定并保证最短保持；SD先回低速、CS/MOSI空闲、提供初始化时钟后重建初始化。恢复时同时撤销未完成SD/BMP/FIFO写入、挂起翻图和显示提交/音频事件；不能只复位SD命令层留下上层等待。第一版以受控重启图像链路、黑屏静音直到首图为主，不在本轮同时引入复杂的保图热插拔。
4. 可用的用户恢复方式：自动重试2～3次，仍失败显示E（通信/初始化错误，不把它冒充精确卡检测），停止无休止等待。用户重新插卡后按KEY3可重新初始化并回首图。错误原因内部区分初始化/读超时即可，不引入Watch或永久调试面板。数码管成功后恢复原有1～4图片编号。

初始化等待、token超时和重试间隔需结合实际SD卡启动时间选取并参数化；不通过无限重试或只加固定开机延迟掩盖协议缺陷。若软件重新初始化后某卡仍不能恢复，再用断电恢复对照判断是否涉及卡内部状态/供电；没有SD电源开关，不能承诺所有异常都等价于卡断电。

## 验证范围

- 现有两项缺陷复现：diagnostics/history/sd_recovery/tb_sd_recovery_gaps.sv，ModelSim10.6e编译和仿真0错误0警告；PASS REPRO仅代表缺陷成功复现，绝不是恢复修复通过。
- 后续至少覆盖：发送命令时的残留字节、CMD0无响应后恢复、初始化延迟、token缺失、数据区中断/CRC失败、在命令/数据中途KEY3复位、重插后首次有效图片及单次提示。使用保留卡侧状态的SD模型，不能随FPGA复位把卡也一起恢复。
- 上板复现用户三种操作，多轮复位和读图中复位，记录超时能否到E、自动重试及重插KEY3能否恢复。用已验收S8固定bit做同操作对照，可区分原有缺陷与S9触发概率变化。
- 原S9顶层测试只对PLL/复位/音频路径做行为模型验证，SD MISO固定空闲，未验证真实SD卡热复位和拔卡。先前五组复位PASS不能证明这三种场景通过。

## 当前临时操作

停止密集翻图，重新插好卡，按KEY3重试；若仍卡0，断电重上并按现有方式下载固定bit。此为临时恢复，不能替代修复，也不保证单次KEY3必然恢复。S9仍停留问题处理阶段。
