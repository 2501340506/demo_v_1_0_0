# 图片转场特效分阶段修改计划（v0.11.0 草案）

日期：2026-10-10；S1 实施更新：2026-10-11。当前正在执行 S1 本地验证与构建，上板结论尚未取得。

## 1. 范围、基线与回退

- 开发基线：当前 main / v0.10.0，提交 b192c03；原目录功能分支 `feature/image-transitions`，不新建 worktree。
- 总回退：`releases/v0.10.0/demo.bit`；后续各阶段保留固定候选，失败回退上一已验收阶段。
- 目标：手动上一张/下一张平滑淡出淡入；AUTO 增加从黑底水平揭示新图；继续保留缓存、重扫、字幕、时间和提示音。
- 默认单侧转场 16 视频帧；60 fps 下单侧约 0.267 秒，完整淡出+淡入至少约 0.533 秒，另加帧对齐与显示提交等待。不是整个过程 0.27 秒。
- 本版不实现新旧两图交叉混合、旧图背景上的真正 Wipe、画面平移滑动或圆形扩散。这些需要另行设计像素读取/地址调度，不能把黑底揭示当作已经完成。
- 关闭转场时保持原显示提交路径和 RGB 透传，作为同版对照及定位入口。
- 工作区原有 `问题小记录.txt` 修改保留，不纳入本任务提交；既有两个 detached worktree、TD 本机输出及 best_result 保留。

## 2. 阅读依据与现状

已读取用户指定课程 Markdown，以及同名目录的 `_说明.md`、`video_fade_transition.v`、`frame_blend.v`。外部路径标题为第十课，正文和说明仍写第9课，引用时以文件路径和实际代码为准。

| 当前文件 | 已有行为 | 对方案的影响 |
|---|---|---|
| `SD/media_player_control.v` | next/previous 待处理方向、AUTO 计时、请求接受握手 | 不用仅支持 next 的课程模块替换播放器；保留忙时方向缓存 |
| `SD/media_frame_cache_control.v` | 四 bank、命中/预载、失败重试、重扫保留旧显示 bank；图片准备好才发 display_request | 转场应拦截显示提交，而不是先黑屏再请求读卡 |
| `SD/sd_card_bmp.v` | cache_display_request 转换为 bank + display_commit_request toggle；真实 ack 回传缓存 | 在此适配器增加允许提交条件，保留真实 ack 语义 |
| `SD/frame_fifo_read.v` | S_ACK 结束时锁存读取地址并回传 display_commit_ack | 保留唯一实际换 bank 点，不用转场完成信号冒充读端确认 |
| `SD/media_frame_reader.v` | 单路读 FIFO、每像素一份 RGB、64 字 burst | 四图驻留不等于已有两路同坐标像素 |
| `audio/media_commit_cdc.v` | 实际提交后向像素域发送 media_update/image | 可用于确认新图已提交，不用预载完成触发提示音 |
| `top_tf_hdmi_audio.v` | vout_data → 状态 OSD → 滚动字幕 → 时间 → 半透明底条 → HDMI | 图片转场插在 vout_data 与状态 OSD 之间 |
| `osd/osd_pixel_position.v` | 低有效 VS 下降沿为 frame_start；首有效像素另有事件 | 沿用项目时序，不能照课程统一写成 VS 上升沿 |

当前视频为 24 位 RGB，video_x 在有效区为 0..639，同时覆盖整行消隐计数；遮罩只用于 DE 有效区。读 FIFO、video_delay 已有对齐关系，不随意改动。

基线发布报告为 11,748 LUT、6,637 寄存器、4 BRAM、2 DSP、1 PLL；Setup +0.102 ns、Hold +0.019 ns。以上是历史基线数据，不是转场版本验证结果；新增 RGB 运算后必须重新检查完整路由时序。

## 3. 课程可借鉴部分与需修正之处

可借鉴四状态思路、按帧更新进度、toggle 握手、转场关闭旁路和 OSD 前插入效果层。

不能原样移植的部分：

1. 示例只有 next 接口，也没有加载失败恢复路径。先淡出再向播放器发请求，读卡失败可能一直等 index_commit 而保持黑屏。本项目改为目标缓存就绪后才启动淡出。
2. 示例 Wipe 只输出控制量；讲义引用的 old_frame_rgb/new_frame_rgb 没有对应读链路实现。自动轮播“不能预知”只是课程接入位置造成的限制，本项目可在实际显示提交前拦截 AUTO。
3. `frame_blend.v` 输入为两路 RGB444（12 位），当前是单路 RGB888（24 位）；其组合运算和实际 DSP 数量需综合确认，不按说明中的固定数量承诺资源。
4. 示例 `ramp_out` 固定 5 位，而 FADE_FRAMES=32 时内部 CNT_W=6，零扩展表达式不成立；首版固定 16 帧与关闭两种配置，若开放参数再统一端口宽度。
5. 课程 /256 会使全亮像素变暗一档，且某段示例将 RGB 注册一拍却没同步控制信号。本版全亮精确透传、全黑精确为零；任何新增流水线必须同时处理 HS/VS/DE/X 和 OSD 坐标。
6. 示例把空闲时 index_commit 当作 AUTO，无法区分首图、重扫和其他提交。本版在控制域保存请求来源，不能只看提交或图片编号猜来源。
7. 不直接复制“忙时丢弃所有新按键”策略。当前播放器已有每方向一项 pending，本版继续保留；后续目标相对实际已提交图号计算，不提前缓存过时索引。

## 4. 推荐架构：缓存就绪后转场、全黑才换 bank

```mermaid
flowchart LR
    A[按键或 AUTO] --> B[现有播放器与四 bank 缓存]
    B --> C[目标图已就绪 display_request]
    C --> D[转场协调器：淡出]
    D --> E[全黑后允许原显示适配器提交]
    E --> F[读端帧边界锁存 bank 并确认]
    F --> G[缓存提交与原音频 CDC]
    G --> H[新图淡入或黑底揭示]
```

### 4.1 控制流程与接口约定

建议新增 `video_transition_control.v`，分控制域事务管理与像素域效果状态机，项目中使用现有高有效复位约定。

- 控制域在 `ctrl_request_accept` 时保存来源：手动或 AUTO。首图及重扫恢复的提交单独标记为旁路，不沿用上一次来源。
- 缓存发出 `cache_display_request` 后，image/bank 已稳定且目标可读。协调器一次性接受该事务并置本地 busy，通过保持数据+请求/确认握手把效果类型送入像素域。
- 像素域在下一 frame_start 开始淡出。进度到全黑后发回允许提交事件；控制域才更新 disp_buf_idx 并翻转原 display_commit_request。
- 原读端 ack 经既有同步返回后，仍立即回给缓存，更新 current_image/current_bank 并走原 committed_valid → media_commit_cdc。不能为了等淡入完成而延迟真实 ack，否则缓存状态与实际读 bank 会脱节。
- 新图提交确认到达像素域后先锁存，再在 frame_start 开始淡入/揭示；确认到来时维持全黑，避免帧中突然露图。原 `audio_update` 可作为这一确认来源，但不改变其脉冲或 ready 消费方式。
- 像素域效果结束回传 done，释放控制域 busy。busy 在本地接受事务的当拍置位，不仅依赖晚到的像素域同步反馈。
- 播放器 `load_busy` 使用 `foreground_busy || transition_busy`；同时禁止 busy 期间向缓存接受下一前台请求。保留 next/previous pending，完成后再按新 current_image 计算下一目标。
- AUTO 在整段转场忙期间暂停并清零间隔计数，恢复全亮后重新计时。已有手动活动抑制 AUTO、切换模式重新计时的规则保留。

控制域建议接口语义：待显示事务 valid/ready、事务来源、允许实际提交的 permit、真实提交完成、整体 busy；像素域使用 start/kind、black_ready、commit_seen、done。具体端口名实施时统一，握手语义先锁定，避免多个模块都认为自己拥有 bank 切换权。

### 4.2 用户操作和正常失败场景

| 场景 | 建议行为 |
|---|---|
| 手动上一张/下一张，目标命中 | 旧图淡出 → 黑场提交 → 新图淡入 |
| 手动未命中 | 原画面保持，目标加载成功后再转场；失败保留原图和现有错误提示 |
| AUTO | S1 先使用相同淡出淡入验证统一流程；S2 改为淡出 → 黑场提交 → 从左到右黑底揭示 |
| 首次出图、重扫后的首图 | 保持原帧边界硬切，不套用 AUTO 特效；后续常规切图启用效果 |
| 同 bank 重复提交、单图循环 | 保留现有提交/音频语义，跳过视觉转场；不能仅按图号相同判断重扫新内容 |
| 连续按键 | 沿用每方向一项 pending；不增加任意长度事件队列 |
| 转场中重扫 | 锁存一项重扫请求，当前转场和在途显示提交完成后执行；阻止新的前台切图，先重扫再处理后续输入 |
| 复位 | 清除转场和跨域握手状态，按现有启动流程恢复 |

重扫延迟期间要将其计入播放器不可用条件，保留 rescan 最高优先级，避免转场结束同拍又接受下一次手动/AUTO 请求。已发出的显示提交继续完成，不撤回、不提前释放 bank。只处理上述真实操作，不增加无依据的重试/超时体系。

### 4.3 像素处理

建议新增 `video_transition_pixels.v`：

- 位置：`vout_data → transition_rgb → 原 OSD 链路`；OSD 字形、滚动速度、UART 更新、时间继续独立运行，转场黑场仍可看到字幕与状态。
- 固定 16 帧采用 0..16 的 5 位 level，`channel_out = (channel * level) >> 4`，乘积显式使用 13 位；level=16 精确透传，level=0 精确全黑。这样只需较小权重运算，无通用除法器。实际映射资源由 TD 报告决定。
- 优先组合 RGB 路径保持零额外像素延迟；若路由不满足时序，再将 RGB 与 HS/VS/DE/X 整体统一寄存，不只寄存颜色。
- S2 水平揭示使用 `boundary = progress * 40`，DE 内 x < boundary 显示当前新图，其余显示黑；progress=16 完整显示 640 列。它明确是黑底揭示。
- alpha/level、遮罩方向、边界和效果使能均在帧消隐边界生效，一帧有效区内保持稳定。跨域确认只锁存，不直接驱动组合亮度。
- 保留现有 reader、SDRAM 调度、64 字 burst 和 RGB 高 24 位取数。不得把四 bank 升级扩大成读架构重写。

### 4.4 真正新旧图 Wipe 的后续边界

若后续要求“左侧新图、右侧旧图”，需设计按行/分段读取不同 bank 或双路取数，并处理 burst 边界、FIFO 顺序和旧 bank 生命周期。它不必天然等于读两张完整帧，但当前工程没有该能力，必须单独测带宽与时序。真正交叉淡化才需要每个坐标两份像素；不能仅新增 frame_blend 就宣称完成。此扩展另立计划，不作为 v0.11.0 默认承诺。

## 6. 阶段和验收门槛

### S0：方案与基线（本次）

完成文档/代码比对、分支与工作区检查、方案和交接。计划标签 `v0.11.0-plan.1`。只有文档，无 bit，无 local/board 标签。

### S1：统一提交协调 + 淡出淡入

先验证协调器与像素模块，再接生产；手动两个方向和 AUTO 暂用统一淡出淡入，首图/重扫旁路。无需为独立模块子步骤额外造硬件候选。

专项：帧中请求不改变本帧亮度；16 帧阶梯和黑/全亮端点；允许提交前不换 bank、每事务只提交一次；真实 ack 后开始恢复；忙时 pending 保留、AUTO 重计时；缓存未命中/坏图不提前黑屏；转场中重扫最终完成。关闭配置与原链路行为对照。

联合验证：真实缓存+reader+SDRAM 模型+视频时序+全部 OSD+音频 CDC，检查整帧 RGB、图号与提示音一一对应；重点观察首行、末列和帧提交附近，无新图提前露出、错位或欠读。

运行直接相关的缓存/控制/读写回归，并复用 `diagnostics/osd/run_system_timestamp.ps1` 的完整三层 OSD 场景及相关 UART/时间测试；脚本必须明确打开新效果配置，不能默认旁路却声称覆盖转场。旧硬切像素断言仅保留在旁路测试，开启效果用对应输出期望。

完整 TD 检查资源、Setup/Hold 和约束覆盖变化；不通过就最小修复并重新出候选。交付 `releases/v0.11.0/s1-local.1/demo.bit`、说明、实际报告和变更源码，标签 `v0.11.0-s1-local.1`。

上板重点：上一张/下一张/AUTO 淡变、缓存加载等待、连续按键、转场重扫、字幕和 MM:SS 不闪移、提示音只对应真实切图。收到用户确认后建立 `v0.11.0-s1-board.1`，推送分支及本阶段标签，再进入 S2。

### S2：AUTO 黑底水平揭示

在 S1 已验收协调链路上增加水平揭示。手动仍淡出淡入，AUTO 淡出后从左到右揭示；不按图片编号循环额外效果，不新增按键/UART 特效设置。

专项逐像素验证边界 0、40、…、640 及最后一列；AUTO/手动交替时来源无残留，OSD 不被遮罩。相关回归、真实 SDRAM 联合测试及完整 TD 通过后形成 `s2-local.N`，用户确认后形成 `s2-board.N` 并推送。

### S3：最终验收与正式发布

复用 S2 已验收原 bit，验证连续切图、AUTO、UART 字幕、重扫恢复、提示音及持续运行；建议运行 20 分钟，同时安排 Flash/完全断电冷启动，按实际反馈记录，未执行项单独保留边界。

源码/bit 不变时不重新构建、不额外建立无意义 local 标签；若发现问题需改 RTL，则重新出递增候选并重新验收。完成最终记录后发布 `v0.11.0`，文档归档至 `docs/history/<完成日期>/image-transitions/`，按执行规则合并 main、推送并核对。

- 保留计划后的字幕修改提交 b76ec4f/d3c7996；实际开发起点包含它们，不恢复旧字模或旧默认字幕。

- 许可控制 disp_buf_idx/display_commit_request 的发出；cache_display_ack 保留真实读端同步确认。前序仅 lint 通过的接法不正确，已替换，不作为阶段验收证据。
- 固定 16 帧，亮度 level=0..16，乘积取 [11:4]。像素层不再额外锁存一帧，直接使用像素域帧边界寄存器，避免多延迟一帧导致许可早于实际黑屏。
- S1 手动和 AUTO 使用同一效果，不需要跨域传来源；来源分类随 S2 的不同效果接入。首图/重扫恢复依据 first_image_committed 旁路，同 bank 依据 bank 相同旁路。
- 转场整体 busy 参与播放器 load_busy 和缓存前台请求使能。重扫请求锁存后等待转场完成；真实提交后 busy 仍持续到淡入结束。
- 顶层 TRANSITION_ENABLE 默认 1；sd_card_bmp 默认 0，供旧独立测试与明确旁路使用。启用转场联合测试显式设为 1，并强制要求转场观测标记。
- 背景预载可在转场期间结束；联合测试不再等待已错过的 load_start 单拍，而在该场景等待 cache_valid 完成状态。
