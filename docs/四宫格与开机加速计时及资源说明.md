# 四宫格与开机加速：计时与资源

本轮资源包基于当前 G 盘的应用资源读取生成，没有写卡。原有 50 个文件共 52,407,931 字节保留，新增四张 THUMB.BMP 共 590,040 字节。原卡文件、ZIP 内容逐字节回读，四张缩略图重复生成一致。

## 卡资源

每个 `情景模式/<场景>/THUMB.BMP` 固定 256×192、24 位、BI_RGB，147,510 字节。生成保持原菜单的等比例完整显示、黑边及取样坐标。保留 PIC1–4 的原文件名、内容和灾害/阶段标签。

```powershell
py -I -X utf8 tools/make_menu_thumbnails.py --source G:/情景模式 --out <新的输出目录>
py -I -X utf8 diagnostics/disaster_selector/package_fast_assets.py --card G:/ --out <新的打包目录>
```

`thumbnail_additions.zip` 只增加四张缩略图；`full_sd_resources.zip` 含原有 PIC、EDU、PCM、FONT/TEXT 和四张缩略图。解压后的应用目录放在 FAT32 卡根目录。目录名沿用既有资源；无 THUMB 或其校验/读取失败时，固件回退读取该场景 PIC1。资源工具只写输出目录，不向源卡写入。

菜单逐格显示，四格均完成或明确失败后可确认可用项；确认还会验证四阶段目录项和 BMP 头。只有完整 PIC1 写入且在帧边界提交后才退出菜单。PIC2–4 在后台缓存；未缓存阶段请求优先于后续预取，正在读取的文件先完成，当前完整图保持到目标完整帧提交。普通文件失败可手动重试；物理 SD 超时停止本次传输，可返回菜单后重新扫描/复位。取消发生在所选资源已替换缓存后，会重载原应用首帧；此前取消保留原页和 AUTO。

## 实板计时

性能目标为菜单 ≤1000 ms、确认至完整首图 ≤1500 ms、上电真实宣传首图争取 ≤2000 ms，均尚待实板测量。基线 v0.22.0-s1-local.1 和新候选使用同板、同卡、同显示器，每项各 10 次，报告中位数和最大值。

```powershell
py -I -X utf8 diagnostics/disaster_selector/summarize_fast_timing.py board.csv --template
# 填入实际测得的 elapsed_ms 后：
py -I -X utf8 diagnostics/disaster_selector/summarize_fast_timing.py board.csv
```

`boot_power` 从上电到真实宣传首帧完整显示，包含 Flash 配置和显示器锁定；`boot_reset` 从复位释放计时；`menu` 从空闲状态 SW3=1 到四格真实图/明确失败且可确认；`confirm` 从确认到所选完整首帧可操作。记录卡型号、冷启动/热复位、SW3 初值、资源版本及是否旧卡回退。不能用启动背景、黑屏结束或单格出现代替结束条件。

生产配置 `UART_LOG_ENABLE=0`，固定候选不输出串口日志。如需板内分段记录，单独将顶层该参数设为 1，恢复 timing.sdc 中三条 `UART_TX_ON` 约束并重新完整构建；该调试 bit 需要独立时序验收。现有 UART 格式的 T 是复位后的十六进制毫秒，115200 波特。启动横幅保留历史文字，不能据此判断固件版本。

```powershell
py -I -X utf8 diagnostics/disaster_selector/parse_fast_timing.py uart.txt --out <新的解析目录>
```

解析生成 events.csv、intervals.csv。INIT_OK 标识 SD 初始化完成；WAIT 的 P=E 为 SDRAM 就绪，P=8 为头预检完成，P=9/A/B 为菜单进入/就绪/确认，P=4/5 为源解码完成/写入排空，P=6 为延后可选资源完成。LOAD→P4/P5 区分解码和内存排空，COMMIT 为完整帧提交。目录发现和图片头预检可出现多段 SCAN_START，需结合 P8 和原事件查看；它们并非每个独立硬件阶段的专用探针。FPGA 配置及 HDMI 锁定需外部录像/示波器测量。

事件先在控制域排队，标记存在数个周期的仲裁延迟；毫秒分辨率不用于比较微小时序差异。每个输入日志只含一次启动，缺失端点不补值；出现 DROP 必须重测，不能把不完整日志当作验收数据。

## S0 可重复仿真基线

`run_fast_metrics.ps1 -RunName <新名称> -Baseline` 从 31de2b0 提取只读基线；去掉 -Baseline 测当前源码。专项传输模型直接提供扇区，不模拟 SPI 初始化、Flash 或显示器锁定。PIC 是 2×3 测试图并缩放到 640×480，THUMB 是实际 256×192，因此仿真扇区数不能当作实际卡的读取量对比，也不能把周期换算为板级提速结论。

| 测试 | 基线周期 | 当前周期 | 含义 |
|---|---:|---:|---|
| case0 旧卡菜单进入→就绪 | 10,122,406 | 2,717,407 | 只读各场景 PIC1，取消其余完整图校验 |
| case11 新卡菜单进入→就绪 | 10,122,406 | 1,786,025 | 原生缩略图直写，省去放大和再次抽样 |
| case16 含 FONT/TEXT 的启动→首帧 | 684,463 | 682,923 | 可选 BIN 实际读取在首帧提交之后 |

证据目录：`diagnostics/output/fast_metrics_baseline03`、`fast_metrics_current18`；每个目录含 case0/11/16 的 metrics 文本。实际卡的 16 张 PIC 全图合计约 19.66 MB，本轮菜单四张缩略图仅约 0.59 MB；文件字节数仅说明工作量变化，不包含 FAT 和扇区开销。
