## 4. 音频消费链与 CDC

| 实际链路/实例 | 端口、时钟及含义 | M4要求 |
|---|---|---|
| sd_card_bmp.g_audio.u_stream（audio/fat32_pcm_stream.v） | clk=SD控制域；enable/audio_found/first_cluster/file_size/卷几何；file_valid/byte→player_ready，sector_permit/player_stopped；stopped/error_code/loop_count | 当前无单次和自然EOF端口；READ完成会重新START，≤512字节走REPLAY_REQ/OUT。两个循环分支都需受loop_enable控制，不只改长文件 |
| g_audio.u_player（audio/pcm_stream_player.v） | wr_clk=SD、rd_clk=transition_pix_clk；file_valid/byte ↔ file_ready；play_enable、sector_permit、buffer_low、stopped；sample_valid/left/right ↔ sample_ready | FIFO停止排空已有握手，但无带会话自然EOF。需要明确最后源样本计数及排空，不拿stopped当正常播放结束 |
| sd_card_bmp.g_scenario.events（scene_event_cdc.v） | sample_accept=bgm_valid && bgm_ready，帧输入transition_frame_start；pix域8位Gray累计，SD域sample_tick/frame_tick | 此为文件源经mux、主音量前的实际接受点，可计进度且音量0有效；计数跨域不能漏回绕，重会话须带身份，复位/排空后再启动 |

| top.u_audio_source_mux | bgm_valid/ready/left/right/active接wav；pcm_media_tone接arp；out_valid/ready接主音量 | wav_active=0会回到提示音；宣传无VOI或播完需显式零音频/静音选择，不能漏出提示音或旧警报 |

## 5. 按键、参数及新控制模块边界

生产 `top.u_switch_mode_control` 同步/消抖 `{sw2,sw1}` → switch_mode；`sd_card_bmp.u_mode_key_control` 输入clk/rst/enable/key1/2/4/mode，输出previous/next/rescan/auto_toggle、adjust_decrease/increase/restore/select及scene_mode/next/warn/speed。现 `mode!=0` 或 `!scene_allowed` 清除内部active，必须在M3改为应用请求与ui页分别管理。参数侧保留 `top.u_adjust_control` 和 `u_adjust_cdc`；`adjust_osd_overlay` 的speed_visible当前优先占同一显示区，M5改参数页优先。

新 `publicity/app_mode_control.v`（建议）拥有目标预检、busy、app/resource_set/version及切换事务；新 `publicity/publicity_control.v`（建议）拥有四页、previous/next/AUTO、完整可见计时、同会话voice_done/error锁存。请求目标页保持到request_ready，当前页只在display_committed更新；两控制器在M3只实现静态手动，M4再开启宣传AUTO。原 `scenario_fsm` 在M3补ui_play推进门控和安全退出，保留终态帧门槛、预警和速度。

M2–M5每次改变端口后用精确模块搜索检查活动生产/诊断例化，保留旧参数关闭模式；旧releases源码冻结。首次接生产即执行相应专项、回归与TD，不用本清单代替实际验证。
